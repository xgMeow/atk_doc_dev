# ATK Markdown 公式检查与修复工具

## 核心原则

1. **只改分隔符，不改内容**：只修复公式外围的分隔符和空行，不修改公式内部的任何字符、变量名、上下标、单位、空格或对齐环境。
2. **最小改动**：每次 Edit 只改一个问题的精确范围，不顺手格式化无关内容。
3. **改后即验证**：每修复一处，立即 Read 该文件相关行确认改动正确，分隔符成对、未破坏上下文。
4. **不确定则保留**：无法 100% 确定是公式时，保留原样并记入报告。
5. **仅手动触发**：此技能不根据上下文自动激活。
6. **不主动构建**：完成修复后不要运行 `npm run build:standalone`，用户自行验证。

## 检查范围

默认检查以下 Markdown 文档目录里的所有`.md`文档：

- `src/en`
- `src/zh`

如果用户明确指定文件或目录，以用户指定范围为准，不扫描其他目录。

## 识别公式 vs 非公式

在扫描和修复前，对每一处 `$`、`\[`、`\(` 候选进行判断：

### 肯定是公式（修复）

以下特征同时出现 ≥2 个，可以确定是公式：

- 包含 LaTeX 命令：`\frac`、`\sum`、`\int`、`\prod`、`\lim`、`\sqrt`、`\partial`
- 包含希腊字母：`\alpha`、`\beta`、`\Delta`、`\varepsilon`、`\theta`、`\lambda`、`\pi` 等
- 包含数学符号：`\infty`、`\pm`、`\times`、`\div`、`\cdot`、`\leq`、`\geq`、`\neq`、`\approx`、`\equiv`
- 包含对齐/矩阵环境：`\begin{aligned}`、`\begin{matrix}`、`\begin{cases}`、`\begin{array}`
- 包含 `\left`/`\right` 括号对
- 包含上下标 `_` 或 `^` 修饰 LaTeX 命令（如 `x_i`、`\hat{x}`）
- 包含 `\text`、`\quad`、`\qquad` 等 LaTeX 排版命令
- 成对的 `$...$` 或 `$$...$$` 之间的内容全是数学符号/变量名

### 肯定不是公式（跳过）

- 在 fenced code block（` ``` ` 或 `~~~`）内
- 在行内代码反引号 `` ` `` 内
- 价格或货币：`$100`、`$1,234`、`100$` —— 数字紧跟在 `$` 后或 `$` 紧跟前置数字
- Shell/环境变量：`$PATH`、`$HOME`、`${VAR}`、`$(cmd)`
- 模板变量占位符：`${name}`、`$name`
- `$` 只出现一次（不成对）且上下文无 LaTeX 命令
- `$` 在代码示例、命令、路径、URL 中

### 存疑（保留原样并报告）

- `$` 成对但内容极短（1-2 个字母），上下文不涉及数学 —— 可能不是公式
- `$` 紧随中文文字无空格（如 `参数$x$`），且文档其他公式也无空格习惯 —— 保留
- 分隔符跨越多行但未对齐、未缩进，无法确定边界

## 公式格式规范与修复规则

### 1. 块级公式：`\[...\]` → `$$...$$`

**查找方式**：用 Grep 在目标范围搜索 `\\\[`，再逐文件 Read 确认上下文。

**修复规则**：

原始形式（独占一行）：
```markdown
\[
a^2 + b^2 = c^2
\]
```
修复为：
```markdown
$$
a^2 + b^2 = c^2
$$
```

原始形式（与文字同行）：
```markdown
根据公式 \[E = mc^2\] 可知
```
修复为（公式拆为独立块）：
```markdown
根据公式：

$$
E = mc^2
$$

可知
```

**特别注意**：
- 如果 `\[...\]` 内只是简短符号（如 `\[x\]`），且上下文是将它作为行内引用，改为 `$x$` 保留在行内。
- 如果 `\[...\]` 在列表项、引用块、表格内，保证转换后的 `$$...$$` 保持正确的缩进层级。

### 2. 行内公式：`\(...\)` → `$...$`

**查找方式**：用 Grep 在目标范围搜索 `\\(`，再逐文件 Read 确认上下文。

**修复规则**：
```markdown
速度为 \(v\)，时间为 \(t\)。
```
修复为：
```markdown
速度为 $v$，时间为 $t$。
```

**特别注意**：
- `\(...\)` 内如果包含 `\\frac`、`\\sum`、`\\int`、`\\begin` 等块级特征 → 改块级 `$$...$$`，并将公式拆为独立行。
- 一行内多处 `\(...\)` 逐一替换，每处只改自己的分隔符对。

### 3. 规范块级公式空行

块级公式 `$$...$$` 前后各保留一个空行。

**正文到公式**：
```markdown
上一段文字。

$$
E = mc^2
$$

下一段文字。
```

**列表项中的公式**（保持缩进，不破坏列表结构）：
```markdown
1. 第一步说明。

   $$
   x = \frac{-b \pm \sqrt{b^2 - 4ac}}{2a}
   $$

2. 第二步说明。
```

**标题后紧跟公式**：标题与公式之间保留一个空行。

**两个相邻块级公式之间**：各为一个独立的 `$$...$$` 块，中间保留一个空行，不要合并为一个 `$$...$$` 块。

### 4. 修复未闭合或混用的分隔符

- `$...$$` 混用 → 根据公式复杂度决定统一为 `$` 或 `$$`
- 只有开 `$$` 无闭 `$$`（或反之）→ 如果可确定公式边界则闭合，否则报告
- `\[...$$` 或 `$$...\)` 等混用 → 统一为 `$$...$$`

## 工作流程

### 第1步：列出待检查文件

对每个目标目录，用 Glob 列出所有 `*.md` 文件：
```
Glob: 01-安装/**/*.md
Glob: 02-案例教程/**/*.md
...
```

汇总出完整的文件清单。

### 第2步：批量扫描定位问题

对文件清单中的文件，用 Grep 搜索以下模式（每种模式一次搜索），记录命中文件与行号：

| 搜索目标 | Grep 正则 | 说明 |
|----------|-----------|------|
| `\[` 块级公式 | `\\\\\[` | 查找 `\[` 作为块级公式开头 |
| `\]` 块级公式 | `\\\\\]` | 查找 `\]` 作为块级公式结尾 |
| `\(` 行内公式 | `\\\\(` | 查找 `\(` 作为行内公式开头 |
| `\)` 行内公式 | `\\\\)` | 查找 `\)` 作为行内公式结尾 |
| 可疑 `$$` | `\$\$` | 查找所有 `$$`，检查是否独占行 |

Grep 时排除 `node_modules/`、`.git/`、`dist/`、`build/` 等构建产物目录。

将命中结果汇总：`文件路径:行号 → 问题类型`。

### 第3步：逐文件排查与修复

对每个有命中的文件：

1. **Read 完整文件**（或命中行前后 20 行上下文）。
2. **逐处判断**：按"识别公式 vs 非公式"标准判定是否需要修复。
3. **排除 code block**：命中的行如果在 fenced code block 内（`` ``` `` 或 `~~~` 之间）、行内代码反引号内、或缩进代码块（4空格/1 tab 开头）内 → 跳过。
4. **对确定是公式的**：使用 Edit 工具精确替换，只改分隔符。
5. **改后立即验证**：Read 改动行确认分隔符成对、上下文完好。
6. **记录存疑项**：将不确定的记入报告清单。

### 第4步：输出报告

完成所有修复后，输出最终报告。

## 上下文感知修复要点

修复时必须考虑公式所在位置的上下文：

**表格内**：
```markdown
| 参数 | 公式 |
|------|------|
| 速度 | $v = at$ |
```
表格单元格内的简短公式用行内 `$...$`，不要拆行。

**引用块（`>`）内**：
```markdown
> 根据公式：
>
> $$
> F = ma
> $$
```
保持引用块的 `>` 前缀和缩进。

**列表项内**：
```markdown
1. **第一步**：计算 $E = mc^2$，其中 $m$ 为质量。
```
列表项内的行内公式不改块级；块级公式保持缩进。

**紧邻中文无空格的行内公式**：
如 `参数$x$的值` → 保持原样，不加空格。分隔符边界是否需要空格以文档已有风格为准。

## 不自动修复规则

以下情况只报告，不修改：

- 公式分隔符在代码块、行内代码、代码示例说明中。
- `$` 可能表示货币、Shell 变量、模板变量或普通文本（按"识别公式 vs 非公式"标准判定存疑）。
- 公式跨越多层 Markdown 结构（如跨列表项、跨表格单元格），自动拆分可能改变语义。
- 多处公式分隔符嵌套，无法确定正确闭合边界。
- 用户明确要求只检查不修复。

## 最终报告格式

全部修复完成且无疑问：

```markdown
公式检查完成。共修复 N 处，无需确认的项目。
```

存在不确定项：

```markdown
公式检查完成。共修复 N 处，以下 M 处需要你确认：

1. `文件路径:行号`
   - 原内容：`...`
   - 不确定原因：...
   - 建议：...
```

全部跳过（无确定性修复）：

```markdown
公式检查完成。未发现需要修复的公式问题。
```

## 禁止事项

- 禁止修改公式内部的变量名、上下标、运算符、数值、单位、对齐环境。
- 禁止修改代码块（fenced/indented/inline code）中的任何内容。
- 禁止把所有 `$...$` 批量改成块级公式。
- 禁止把货币 `$`、Shell 变量 `$`、模板变量 `$` 误判为公式。
- 禁止为了统一风格而修改本来能正确渲染的公式。
- 禁止在无法确定时强行修改 —— 存疑即报告。
- 禁止修改后不 Read 验证就直接进入下一处。
