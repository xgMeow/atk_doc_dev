# ATK CONNECT 命令文档格式化

将命令文档规范化，确保 `ConnectCommandSummary` 组件的提取器能正确解析。**只改格式，以原文为基准，不新增原文没有的章节或内容。**

## 提取器契约（必须满足）

组件提取逻辑位于 `.vuepress/components/ConnectCommandSummary/extractCommandInfo.mjs`：

- **命令名** = `#` 一级标题文本
- **作用** = `## 作用` 之后、下一个 `##` 之前的第一段纯文本（跳过代码块取第一段）
- **语法** = `## 语法` 之后第一个代码块的内容

三个字段缺一不可，且必须遵守以下顺序和间距规则：

```
# <命令名>

## 作用

<一个段落>

## 语法

```
<命令语法>
```
```

**关键约束**：`## 作用` 和 `## 语法` 之间只能是作用描述文本，不能插入代码块、表格或其他标题，否则提取器取不到作用。

## 必须处理的三个章节

### `#` 命令名

和原文完全一致，不改大小写、空格、下划线。

### `## 作用`

- 保持原有表达，只改格式，不改措辞。
- 合并为一个段落，不换行、不分点。
- 关键术语 `**加粗**`，命令名/参数名用 `` ` `` 反引号。

### `## 语法`

- 标题统一为 `## 语法`（旧格式的 `## 用法` 改标题名即可）。
- 无语言标记代码块，内容与原文完全一致，不做任何修改。
- 该章节只放一个语法代码块，不要加其他代码块。

## 其他章节（原文有则保留并规范化，没有则不加）

以下章节都不是必须的——**原文有什么就规范化什么，原文没有就不要新增**：

### 原文有 `## 说明`

按内容性质拆分：
- 含表格 → 改为 `## 参数说明`，两列表格（参数/说明），参数名用反引号
- 含段落/列表 → 改为 `## 补充说明`，无序列表
- 两者都有 → 分别建 `## 参数说明` 和 `## 补充说明`

若 `说明` 中有枚举参数列表，在表格下方补 `### <参数名> 取值` 子表。

### 原文有 `## 举例`

改为 `## 示例`，用 `::: details open **描述**` 包裹代码块。描述用短句概括操作场景，**加粗**。时间戳、路径一字不改。

### 原文有其他章节

保留原章节，放在 `## 语法` 之后、`## 示例` 之前（如果有示例的话）。确保不插入到 `## 作用` 和 `## 语法` 之间。

## 旧格式章节名对照

| 旧标题 | 改为 | 说明 |
|--------|------|------|
| `## 用法` | `## 语法` | 只改标题名 |
| `## 说明` | `## 参数说明` / `## 补充说明` | 按内容拆分 |
| `## 举例` | `## 示例` | 补折叠容器 |

## 工作流程

1. 通读原文，确认哪些章节已存在。
2. 确保 `# 命令名`、`## 作用`、`## 语法` 三个必须章节格式正确。
3. 原文已有的其他章节按规则规范化，标题名对齐，格式统一。
4. **不新增原文没有的章节**，除非该章节的内容在原文中以非标题形式存在（如参数说明散落在正文中）。
5. 对照验证清单自检。

## 验证清单

- [ ] `#` 标题为命令名
- [ ] `## 作用` 为一段文本，与 `## 语法` 之间无代码块/表格/其他标题
- [ ] `## 语法` 为无语言标记代码块（`` ``` `` 而非 `` ```bash ``），内容与原文一致
- [ ] 原文有示例的已改为 `::: details open **描述**` 包裹
- [ ] 原文的语法、参数值、时间戳、路径、功能描述措辞未改动
- [ ] 没有新增原文不存在的章节或内容
