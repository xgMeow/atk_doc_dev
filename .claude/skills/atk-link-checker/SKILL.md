# ATK VuePress 链接检查与修复工具

## 何时使用

当用户提出以下任一请求时，应激活此 skill：

- “检查文档链接”
- “修复坏链”
- “检查 VuePress 链接是否正确”
- “检查案例教程/基础使用指南等文档中的链接”
- “检查 OverView 的 link 配置”
- “检查 redirect.ts 的重定向地址”
- 用户要求检查或修复 ATK 文档仓库中的 Markdown 链接、图片路径、锚点、VuePress 路由或重定向地址

## 检查范围

只主动检查以下 Markdown 文档目录：

- `01-安装`
- `02-案例教程`
- `03-基础使用指南`
- `04-理论基础`
- `5.专业使用指南`
- `二次开发教程`
- `发布说明`

额外检查以下 VuePress 配置文件中的链接：

- `.vuepress/components/OverView/OverView.vue` 中模块数据配置的 `link` 字段
- `.vuepress/redirect.ts` 中的重定向源地址和目标地址

除非某个文件是上述范围内链接的目标候选，否则不要主动扫描其他 Markdown 目录。

## 核心原则

1. **逐条核验，禁止盲修**：每个疑似问题都必须查看所在文件、行号、上下文和目标候选，不能只靠脚本结果批量替换。
2. **先判断是否真错**：VuePress 支持多种合法链接形式，不能因为普通文件路径解析失败就认定为坏链。
3. **只修确定性问题**：只有目标唯一、语义匹配、链接形式明确错误时才修改。
4. **不确定就不改**：无法确认正确目标的链接保留原样，最终只报告这些链接并给出建议。
5. **改后必须构建**：完成所有确认修复后，必须执行 `npm run build:standalone`，至少保证能成功打包。
6. **最终报告保持精简**：最终只告诉用户仍不确定、需要用户确认的链接，不输出已修复清单或无问题统计。

## VuePress 合法形式识别

检查前必须考虑以下形式可能都是合法的：

- Markdown 文件路径：`foo.md`、`./foo.md`、`../foo.md`
- VuePress 页面路由：`foo.html`、`./foo.html`、`/foo.html`
- 目录路由：`foo/`、`./foo/`、`/foo/`
- 省略扩展名：`foo`、`./foo`、`../foo`
- 锚点：`#anchor`、`./foo.md#anchor`、`/foo/#anchor`
- 中文路径、空格路径、URL 编码路径
- VuePress 标题自动生成的锚点
- Markdown-it / VuePress 插件生成或支持的自定义锚点
- 静态资源路径、相对图片路径、绝对 public 路径

只有在确认 VuePress 不能解析该链接，或构建明确报错，且正确目标能够唯一确定时，才进行修复。

## 工作流程

### 第1步：确认项目结构

- 确认当前仓库是 VuePress 文档项目。
- 查看 `.vuepress/config.ts`，理解 base、路由、主题或插件配置是否会影响链接解析。
- 查看 `package.json`，确认 `npm run build:standalone` 可用。
- 确认上述检查范围目录和两个配置文件是否存在。

### 第2步：收集候选目标

- 收集检查范围内的 Markdown 文件。
- 收集仓库中的 Markdown 文件作为链接目标候选。
- 收集图片和静态资源文件作为图片路径候选。
- 对 Markdown 标题建立锚点候选，但不要完全依赖脚本生成规则；中文标题、自定义锚点和插件锚点必须谨慎判断。

### 第3步：扫描链接

检查以下链接来源：

- Markdown 普通链接：`[text](target)`
- Markdown 图片：`![alt](target)`
- HTML 图片：`<img src="target">`
- HTML 链接：`<a href="target">`
- VuePress/Vue 组件中明显的链接属性：如 `to`、`href`
- `.vuepress/components/OverView/OverView.vue` 模块数据配置中的 `link`
- `.vuepress/redirect.ts` 中的重定向地址

跳过以下内容：

- 代码块中的示例链接，除非上下文表明它是真实文档链接。
- 纯占位符示例，如 `http://example.com`。
- `mailto:`、`tel:`、`javascript:` 等非文档导航链接。

### 第4步：逐条判断疑似问题

对每个疑似坏链，必须逐条完成以下检查：

1. 打开源文件并查看链接所在行及上下文。
2. 判断链接意图：跳转文档、跳转章节、引用图片、访问外部站点、VuePress 路由或历史重定向。
3. 判断原链接是否可能是 VuePress 支持的合法形式。
4. 查找目标候选，确认是否只有一个合理目标。
5. 对比链接文本、上下文标题、候选文件名和候选页面内容，确认语义是否匹配。
6. 如果修复会改变链接风格，确认是否必要；不要为了统一风格而改动本来有效的链接。

## 自动修复规则

可以自动修复的情况：

- 相对路径层级明显错误，且只有一个语义匹配的目标文件。
- 图片路径明显错误，且只有一个语义匹配的图片文件。
- 大小写不一致，且仓库中只有一个大小写匹配候选。
- `.md`、`.html`、目录路由之间的形式错误导致构建失败，且正确目标唯一。
- 链接指向已重命名文件，且通过上下文和文件内容能确认唯一目标。

自动修复时必须遵守：

- 每次修改前确认所在上下文和目标语义。
- 优先保持该文件已有链接风格。
- 使用最小改动，不做无关格式化。
- 不使用全局批量替换来代替逐条确认。

## 不自动修复规则

以下情况只记录为“不确定链接”，不修改：

- 多个候选目标都可能正确。
- 候选目标存在，但语义和链接文本不明显匹配。
- 锚点可能由中文标题、自定义 `{#id}`、插件或运行时组件生成，无法静态确认。
- `.vuepress/redirect.ts` 中源地址是历史兼容路径，无法判断是否应该保留。
- 外部链接不可访问、超时、重定向异常或需要登录。
- VuePress 可能支持该写法，但静态检查无法完全确认。
- 修复会影响大量文件或需要统一迁移链接风格。

## 构建验证

完成所有确定性修复后，必须运行：

```bash
npm run build:standalone
```

要求：

- 构建成功后，才能认为修复完成。
- 如果构建失败，先阅读错误信息，定位是否由链接问题导致。
- 如果失败原因是确定性链接问题，继续逐条修复并重新构建。
- 如果失败原因与链接无关或无法确认，向用户说明构建失败原因和建议，不要伪装成成功。

## 最终报告格式

最终只输出仍需用户确认的不确定链接。不要输出已自动修复链接清单，不要输出无问题统计。

如果没有不确定链接，简短说明：

```markdown
链接检查和确定性修复已完成，`npm run build:standalone` 构建通过。没有需要你确认的不确定链接。
```

如果存在不确定链接，使用以下格式：

```markdown
链接检查和确定性修复已完成，`npm run build:standalone` 构建通过。以下链接需要你确认：

1. `文件路径:行号`
   - 原链接：`...`
   - 不确定原因：...
   - 建议：...
```

如果构建未通过，使用以下格式：

```markdown
已完成能确认的链接修复，但 `npm run build:standalone` 未通过。

构建失败原因：...

以下链接或问题需要你确认：

1. `文件路径:行号`
   - 原链接：`...`
   - 不确定原因：...
   - 建议：...
```

## 禁止事项

- 禁止用一次全局替换批量改完所有疑似链接。
- 禁止只根据文件名相似度自动修复。
- 禁止为了让构建通过把链接随意改成某个存在路径。
- 禁止将 VuePress 支持的合法链接形式误报为错误。
- 禁止跳过 `npm run build:standalone`。
- 禁止在最终报告中输出冗长的已修复列表，除非用户明确要求。
