# ATK 文档格式化

用于在不改变原意的前提下，整理 ATK 项目中的 Markdown/VuePress 文档，使结构清晰、格式统一、可正常构建与阅读。

## 何时使用

当用户提出以下请求时使用本技能：

- 格式化、整理、规范化 Markdown 文档。

- 优化 ATK 教程、案例、帮助文档、理论说明等文档结构。

- 统一标题、按钮、窗口/对话框、图片、表格、公式、提示块或中文引号格式。

- 用户提供 `.md` 文件并要求“按规范处理”“美化格式”“整理层级”。

不要用于：

- 重写文案、扩写内容、补充技术结论。

- 专项排查链接、图片路径、公式渲染或构建失败。

- 未经用户要求大幅改动章节顺序或删除原文内容。

## 核心原则

1. **只做格式规范化**：保留原文信息、结论、数据、链接和图片路径。

2. **最小必要改动**：只改影响结构、排版、渲染或规范一致性的内容。

3. **先理解后编辑**：完整阅读目标文档，确认文档类型、标题结构和用户特别要求。

4. **不臆造内容**：除 frontmatter `description`、提醒块标题等格式所需的简短归纳外，不添加原文没有的信息。

5. **保护用户改动**：编辑前注意当前文件可能已有未提交修改，只处理用户指定范围。

## 工作流程

1. 阅读目标文档，识别文档类型、现有大纲、图片、链接、公式、表格等格式元素。

2. 先梳理整体标题层级，再处理局部格式，避免边改边造成层级跳跃。

3. 按“frontmatter → 标题 → 按钮/窗口 → 图片 → 表格 → 公式 → 提醒块 → 空行/加粗 → 引号”的顺序处理。

4. 修改后按验证清单自检；若用户要求验证，或修改涉及公式/链接/构建风险，再运行项目构建或相关检查。

5. 汇报时说明改动范围和是否执行验证，不夸大为内容修订。

## 格式规则

### 1. Frontmatter 与 description

- 保留已有 frontmatter 字段，不随意删除或重排重要字段。

- 若缺少 `description`，根据文档核心内容补充 20-50 字的简洁描述。

- 若已有 `description` 但过长、空泛或不准确，可压缩为准确简洁版本。

- 不主动新增 `title` 字段；已有 `title` 保留。

```markdown
---
title: 入门案例
---
```

转换为：

```markdown
---
title: 入门案例
description: 通过创建简单覆盖分析任务，快速上手 ATK 的基本操作流程。
---
```

### 2. 标题与目录层级

- 移除标题前编号：`1.`、`1.1`、`一、`、`（1）`、`1）` 等。

- 标题末尾不要有标点符号。

- 标题层级必须连续，不从 `#` 直接跳到 `###`。

- 同一组并列内容使用相同标题层级。

- 尽量控制在 `###` 以内。

- 独立成行、统领后续内容的加粗短语或编号短语，应改为 Markdown 标题。

- 普通步骤编号不提升为标题；只有统领后续段落、列表、图片、表格或并列模块时才提升。

- 若还有四层或更低级的结构，优先使用列表加粗形式表示，使层级清晰但不冗余。

- 标题应简洁保留原意；若原标题含说明句，将说明句下移为正文。

```markdown
**（1）主界面**
```

转换为：

```markdown
### 主界面
```

```markdown
1）从场景对象选择卫星。支持卫星多选：
```

转换为：

```markdown
1. **从场景对象选择卫星：**

支持卫星多选。
```

推荐层级示例：

```markdown
# 接近分析工具
## 功能介绍
## 功能位置
## 界面介绍
### 主界面
### 选择主目标
### 高级设置界面
```

### 3. 按钮与操作控件

- 具体可点击按钮、菜单项、工具栏控件使用 `<kbd>` 包裹。

- 标题、列表项标题、表头中的按钮名称不使用 `<kbd>`。

- 图标按钮如果已有行内图标，按钮文字仍可用 `<kbd>` 表示。

```markdown
点击 新建 按钮
```

转换为：

```markdown
点击 <kbd>新建</kbd> 按钮
```

```markdown
## 新建
```

保持为标题，不改为 `<kbd>`。

### 4. 窗口、对话框、页面和面板

- 具体窗口、对话框、页面、面板、选项卡名称用中文方括号【】包裹。

- 通用词“窗口”“对话框”“页面”“面板”本身不包裹。

- 已经使用【】且名称正确的内容保持不变。

```markdown
打开新建向导对话框
```

转换为：

```markdown
打开【新建向导】对话框
```

```markdown
在属性窗口中
```

转换为：

```markdown
在【属性】窗口中
```

### 5. 图片与图标

- 独立图片使用标准 Markdown：`![描述](路径)`。

- 独立图片前后各保留一个空行。

- 与文字混排的小图标使用：`<img src="..." alt="..." no-view />`，必须添加 `no-view` 标识。

- 不修改图片路径；除非用户明确要求，不重命名图片文件。

```markdown
上一段文字。

![覆盖时段分析报告](./media/image30.png)

下一段文字。
```

行内图标示例：

```markdown
点击 <img src="./media/add.png" alt="新增" no-view /> 可添加新项。
```

### 6. 段落、列表和空行

- 段落、标题、图片、代码块、表格、提醒块之间保留一个空行。

- 列表项之间加空行。

- 不连续堆叠多个空行。

- 中英文、数字、代码、快捷键之间的空格按原文风格保持一致，除非明显影响可读性。

### 7. 表格

- 多列表格保留表格结构，只规范空格、表头和对齐线。

- 单列表格若只是罗列内容，转换为列表或普通段落。

- 不改动表格数据、单位、数值精度和顺序。

```markdown
| 数值 |
| ---- |
| 500  |
```

转换为：

```markdown
- 数值：500
```

### 8. 加粗

- 加粗标记前后与中文正文之间保留空格，紧邻标点时不强制加空格。

- 不把普通强调内容提升为标题，除非它统领后续结构。

```markdown
设置**高度**为 500。
```

转换为：

```markdown
设置 **高度** 为 500。
```

### 9. 公式

- 块级公式使用 `$$ ... $$`。

- 行内公式使用 `$ ... $`。

- 将 `\[ ... \]` 转为 `$$ ... $$`。

- 将 `\( ... \)` 转为 `$ ... $`。

- 不修改公式含义、变量、上下标、单位和编号。

```markdown
\[ E = mc^2 \]
```

转换为：

```markdown
$$ E = mc^2 $$
```

```markdown
行内公式 \( a^2 \)
```

转换为：

```markdown
行内公式 $ a^2 $
```

### 10. 提醒块

将提示、注意、警告、重要说明等内容转换为 VuePress 容器语法，并补充简洁标题。

| 原文类型 | 目标容器 | 标题示例 |
| --- | --- | --- |
| 提示、Tip | `::: tip` | 使用提示 |
| 注意、Note | `::: warning` | 注意事项 |
| 警告、Warning | `::: warning` | 警告 |
| 重要、Important | `::: important` | 重要说明 |
| 谨慎、Caution | `::: caution` | 谨慎操作 |

```markdown
**注意**：使用前请先保存文件。
```

转换为：

```markdown
::: warning 使用前注意
使用前请先保存文件。
:::
```

普通引用如果表达提示、注意或警告，也转换为提醒块并移除 `>`：

```markdown
> 提示：网格检查前请确保已完成覆盖计算。
```

转换为：

```markdown
::: tip 使用前准备
网格检查前请确保已完成覆盖计算。
:::
```

### 11. 折叠块

仅当长参数说明、长步骤说明或附录内容影响主流程阅读时，使用 `details` 折叠块。不要为了格式统一滥用折叠块。

```markdown
::: details 展开查看完整配置
折叠内容。
:::
```

### 12. 中文引号

- 中文自然语言中的双引号使用中文弯引号：左引号 `“`（U+201C），右引号 `”`（U+201D）。

- 代码、路径、命令、JSON、YAML、HTML 属性、英文参数中的双引号保持直引号 `"`（U+0022）。

- 不确定上下文时，优先保护代码和路径，不做机械全局替换。

正确示例：

```markdown
用户说：“开始计算”。
print("hello")
--config="C:\\config.json"
```

错误示例：

```markdown
用户说：”开始计算“。
print(“hello”)
```

涉及中文引号修改后，用字符检查工具确认：

- U+201C：`“`，左引号。

- U+201D：`”`，右引号。

- U+0022：`"`，直引号，仅代码/路径等上下文允许。

## 综合示例

输入：

```markdown
# 1. 创建场景

1. 运行 ATK.exe，点击"新建一个想定文件"；
2. 打开新建向导对话框，设置场景名称为 CoverageExample；
**注意**：使用前请备份文件。
```

输出：

```markdown
# 创建场景

1. 运行 ATK.exe，点击 <kbd>新建一个想定文件</kbd>。

2. 打开【新建向导】对话框，设置 **场景名称** 为 **CoverageExample**。

::: warning 使用前注意
使用前请备份文件。
:::
```

## 边界情况

- 标题中的按钮名称不加 `<kbd>`。

- 表格、图片、公式中的原始数据和路径不改。

- 普通操作步骤不改成标题。

- 非提示性质的普通引用可保留 `>`。

- 已规范的 VuePress 容器不重复转换，只在缺少标题时补简洁标题。

- 涉及链接路径、图片路径、公式兼容性的大范围修复时，先征求用户确认或改用专项检查。

## 验证清单

完成后逐项检查：

- [ ] Frontmatter 有准确、简洁的 `description`。

- [ ] 标题无编号，末尾无标点，层级连续，并列层级一致，整体不超过必要深度。

- [ ] 伪标题已按实际结构转换，普通步骤编号未误升为标题。

- [ ] 四层或更低级结构已优先用加粗列表表达。

- [ ] 操作按钮使用 `<kbd>`，标题、表头、列表项标题未误用 `<kbd>`。

- [ ] 具体窗口、对话框、页面、面板名称使用【】。

- [ ] 独立图片前后有空行，行内图标使用 `<img ... no-view />`。

- [ ] 段落、列表、代码块、表格、提醒块之间空行合理，无连续多余空行。

- [ ] 单列表格已按语义转为列表或段落，多列表格数据未改动。

- [ ] 块级公式为 `$$`，行内公式为 `$`。

- [ ] 提示、注意、警告等内容使用合适的 `:::` 容器并带标题。

- [ ] 中文弯引号方向正确，代码和路径中的直引号未被误改。

- [ ] 未改动用户未要求修改的链接、图片路径、数值和技术结论。
