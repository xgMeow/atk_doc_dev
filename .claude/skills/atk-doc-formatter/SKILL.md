# ATK 文档格式化

> **手动触发技能。** 不根据上下文自动激活——即使用户在讨论文档格式或 ATK 文档话题，也不要主动调用。仅当用户明确输入 `/atk-doc-formatter`、`用 atk-doc-formatter 格式化`、`调用文档格式化技能` 等指令时执行。

## 核心原则

1. **内容不可变**：只调整格式与排版，不新增、删除或改动原文的任何信息、结论、数据、链接和图片路径。除 frontmatter `description` 和提醒块标题等格式所需的简短归纳外，不添加原文没有的内容。
2. **最小改动**：只处理影响结构、排版、渲染或规范一致性的问题，不做不必要的润色。
3. **先读后改**：完整阅读目标文档后再动手，确认文档类型、标题结构和未提交改动。
4. **如实汇报**：完成后说明改了什么格式问题，不夸大为内容修订。
5. **仅手动触发**：此技能不根据上下文自动激活。

## 适用与不适用

**适用**：统一标题层级、按钮标记、对话框名称、图片格式、表格结构、公式分隔符、提醒块、中文引号、frontmatter 描述、参考文献内联等格式问题。

**不适用**：重写文案、扩写内容、补充技术结论、专项排查链接/图片路径/公式渲染/构建失败，或未经要求大幅调整章节顺序。

## 工作流程

1. 通读全文，识别大纲结构、图片、链接、公式、表格、提醒块等元素。
2. 按 `frontmatter → 标题 → 按钮/窗口 → 图片 → 表格 → 公式 → 提醒块 → 引用 → 段落/空行 → 引号` 顺序逐项处理。
3. 每改完一个类别，对照验证清单自检。
4. 完成后通读全文，确认无内容丢失或语义变化。
5. **不要运行构建命令**，用户自行验证。

## 格式规则

### Frontmatter

- 保留已有字段，不随意删除或重排。
- **不主动新增 `title`**。
- `title` 与一级标题（`#`）不一致时，询问用户以哪个为准；用户确认后优先保留一级标题、移除 `title`。若文档没有一级标题，则保留 `title` 不动。
- **标题与文件名一致性**：检查大标题（优先 `#`，无则取 frontmatter `title`）与文件名（去掉开头数字编号如 `1.`、`01-`）是否一致；不一致时询问用户。`README.md` 以上级文件夹名为准。
- 缺少 `description` 时根据核心内容补充 20-50 字简洁描述；已有描述过长或空泛时压缩为准确版本。

### 标题与层级

**层级规范：**
- 页面主标题 `#` 紧跟 frontmatter；`PathViewer` 等页面组件放在主标题之后。
- 标题层级连续，不从 `#` 跳至 `###`；并列内容层级一致。
- 避免使用 `####` 及更低级标题，需要更细结构时用编号列表、加粗列表项和缩进块表达。

**编号清理：**
- 移除标题前的编号（`1.`、`1.1`、`一、`、`（1）`、`1）` 等），标题末尾不加标点。
- 标题简洁保留原意；原标题含说明句时，将说明句下移为正文。

**标题 vs 列表项的判断：**
- 只有当短语与相邻 `##` 章节同级、统领较长独立内容，或原文已形成稳定同级章节时，才改为 Markdown 标题。
- 编号列表项是同一章节下的并列阶段且统领多个步骤、表格或图片时，写成加粗列表标题：`1. **阶段名称**`。
- 局部配置步骤通常保持普通编号列表项，不要仅因后续有说明或表格就加粗或升为标题。
- 列表项形如"短标题。后续正文"且统领后续段落时，拆为列表项加粗标题 + 缩进正文；若只是普通一步操作，保留原样。

### 按钮、控件、窗口

- 可点击按钮、菜单项、工具栏控件 → `<kbd>`。标题、表头、列表项标题中的按钮名称不用 `<kbd>`。
- 图标按钮已有行内图标时，按钮文字仍可用 `<kbd>`。
- 具体窗口、对话框、页面、面板、选项卡名称 → 中文方括号【】。通用词"窗口""对话框"本身不包裹。已正确使用【】的保持不变。

### 图片与图标

- 独立图片：`![描述](路径)`，前后各一个空行。列表项内的图片同样与上方文字间保留一个空行，并按列表项缩进，不顶格。
- 行内小图标：`<img src="..." alt="..." no-view />`，必须含 `no-view`。
- 不修改图片路径，不重命名图片文件。
- **alt 文本**：缺少或仅写 `image`、`图片` 等无意义内容时，结合上下文补充有意义的描述；原文已清晰则不擅自改动。

### 段落、列表、空行、加粗

- 段落、标题、图片、代码块、表格、提醒块之间保留一个空行，不连续堆叠多个空行。
- 列表项之间加空行；列表项内的段落、图片、提醒块、代码块等块级元素保持与正文一致缩进。
- **列表项内围栏代码块**：围栏标记（` ``` `）和**代码内容每行都须缩进**，与列表项正文对齐。仅缩进围栏标记不缩进代码内容会导致 VuePress 渲染失败。示例：
  ```markdown
  <!-- 正确：代码内容和围栏均缩进 4 空格 -->
  1. 步骤描述

      ```python
      print("hello")
      ```

  <!-- 错误：仅缩进围栏，代码未缩进 — 渲染失败 -->
  1. 步骤描述

      ```python
  print("hello")
      ```
  ```
- 加粗标记前后与中文正文间保留空格（紧邻标点时除外）。
- 编号列表项作为阶段标题时整项加粗：`1. **阶段名称**`，不要写成 `1. 阶段名称` 后直接缩进多段内容。
- 中英文、数字、代码、快捷键之间的空格按原文风格保持一致，除非明显影响可读性。
- 不把普通强调内容提升为标题。

### 表格

- 多列表格保留结构，只规范空格、表头和对齐线，不改动数据、单位、数值精度和顺序。
- 单列表格若仅是罗列内容，转换为列表或段落。

### 公式

- 块级公式 `$$ ... $$`，行内公式 `$ ... $`。
- 将 `\[ ... \]` 转为 `$$ ... $$`，`\( ... \)` 转为 `$ ... $`。
- 不修改公式含义、变量、上下标、单位和编号。

### 提醒块与折叠块

- 提示、注意、警告、重要说明等转换为 VuePress 容器并补简洁标题；普通引用若表达提示/注意/警告语义，也转为提醒块并移除 `>`。
- 已规范的容器不重复转换，只在缺标题时补标题。但如果容器类型与语义明显不匹配（如警告用了 `::: tip`），更正为合适类型。
- `:::` 前后各一个空行。容器内部：`::: type 标题` 后空一行写内容，内容后空一行写 `:::`（空容器除外：`::: type 标题` 后直接 `:::`）。
- 提醒块在列表项内时，`:::` 起止行和内容行均按列表项缩进。
- 容器类型映射（VuePress 规范）：

| 语义 | 容器类型 |
|------|----------|
| 提示、小技巧 | `::: tip` |
| 注释、注意、备注 | `::: note` |
| 信息、说明 | `::: info` |
| 警告 | `::: warning` |
| 重要 | `::: important` |
| 危险、谨慎 | `::: caution` |

- 每个容器携带简洁标题：`::: type 标题`。
- 折叠块 `::: details 标题` 仅用于长参数说明、长步骤说明或附录等影响主流程阅读的场景，不为统一格式滥用。

### 引用与参考文献

- **引用条目是链接（URL）时**：将正文 `[n]` 角标转为内联 Markdown 链接，用被标注词语作链接文本。如 `安装[1]并运行` + 文末 `[1] https://example.com` → `[安装](https://example.com)并运行`。
- **引用条目是纯文本（无 URL 的论文、书籍等）时**：保留原文 `[n]` 角标和 `## 参考文献` 章节不变。
- 转换后从文末 `## 参考文献` 中移除已内联条目；若全部内联，删除整个章节。
- **转换后核验**：编号连续无跳号，正文角标与文末条目一一对应，无遗漏无多余。

### 中文引号

- 中文自然语言双引号 → 弯引号 `“`（U+201C）`”`（U+201D）。
- 代码、路径、命令、JSON、YAML、HTML 属性、英文参数中的双引号 → 保持直引号 `"`。
- 不确定上下文时优先保护代码和路径，不做机械全局替换。
- 修改后检查方向：`“文本”` 正确，`”文本“` 错误。

## 常用转换示例

```markdown
# 1. 创建场景

1. 运行 ATK.exe，点击"新建一个想定文件"；
2. 打开新建向导对话框，设置场景名称为 CoverageExample；
**注意**：使用前请备份文件。
```

转换为：

```markdown
# 创建场景

1. 运行 ATK.exe，点击 <kbd>新建一个想定文件</kbd>。

2. 打开【新建向导】对话框，设置 **场景名称** 为 **CoverageExample**。

::: warning 使用前注意
使用前请备份文件。
:::
```

其他示例：

| 原文 | 转换后 |
|------|--------|
| `点击 新建 按钮` | `点击 <kbd>新建</kbd> 按钮` |
| `打开新建向导对话框` | `打开【新建向导】对话框` |
| `1. 遍历分析` 后接多条缩进步骤 | `1. **遍历分析**` |
| `\[ E = mc^2 \]` | `$$ E = mc^2 $$` |
| `行内 \( a^2 \)` | `行内 $ a^2 $` |
| `安装[1]并运行` + `[1] https://...` | `[安装](https://...)并运行`，移除参考文献章节 |
| `参见文献[2]` + `[2] 某某论文，2020`（无链接） | 保持原样不变 |

## 验证清单

完成后逐项检查：

**结构与元数据：**
- [ ] Frontmatter 有准确简洁的 `description`
- [ ] 页面主标题在 frontmatter 后，页面组件不抢在主标题前
- [ ] 标题无编号、无末尾标点，层级连续，并列一致，不超过必要深度
- [ ] 主流程阶段用标题，阶段内统领多步的条目用编号加粗列表，普通配置步骤未误加粗或误升标题

**行内标记：**
- [ ] 操作按钮用 `<kbd>`，标题/表头/列表项标题未误用 `<kbd>`
- [ ] 窗口、对话框、页面、面板名称用【】
- [ ] 中文弯引号方向正确，代码和路径中直引号未被误改

**块级元素：**
- [ ] 独立图片前后各一个空行，列表项内图片与上方文字间也保留空行
- [ ] 行内图标用 `<img ... no-view />`
- [ ] 列表项内图片、提醒块、代码块等缩进正确；代码块围栏和代码内容每行均已缩进，未脱离所属步骤
- [ ] 段落、列表、代码块、表格、提醒块间空行合理，无连续多余空行
- [ ] 单列表格已按语义转列表或段落，多列表格数据未改动
- [ ] 块级公式用 `$$`，行内公式用 `$`

**容器与引用：**
- [ ] 提示/注意/警告等内容用合适的 `:::` 容器并带标题，前后各一个空行
- [ ] `[n]` 角标中，有 URL 的参考文献已转为内联链接并移除条目；纯文本参考文献保持原样
- [ ] 参考文献编号连续无跳号，角标与条目一一对应

**内容安全：**
- [ ] 未改动链接、图片路径、数值和技术结论
- [ ] 原文信息无丢失、无新增、无语义变化
