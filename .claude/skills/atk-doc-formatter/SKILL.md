# ATK 文档格式化

在不改变原意的前提下，整理 ATK 项目的 Markdown/VuePress 文档，使结构清晰、格式统一、可正常构建与阅读。

## 何时使用

用于用户要求格式化、整理、规范化、美化 ATK 教程、案例、帮助文档、理论说明等 `.md` 文档，或要求统一标题、按钮、窗口/对话框、图片、表格、公式、提示块、中文引号等格式。

不要用于重写文案、扩写内容、补充技术结论、专项排查链接/图片路径/公式渲染/构建失败，或未经要求大幅调整章节顺序、删除原文内容。

## 核心原则

1. 只做格式规范化，保留原文信息、结论、数据、链接和图片路径。
2. 最小必要改动，只处理影响结构、排版、渲染或规范一致性的内容。
3. 先完整阅读目标文档，确认文档类型、标题结构、用户要求和未提交改动范围。
4. 不臆造内容；除 frontmatter `description`、提醒块标题等格式所需简短归纳外，不添加原文没有的信息。
5. 汇报时说明改动范围和验证情况，不夸大为内容修订。

## 工作流程

1. 阅读目标文档，识别大纲、图片、链接、公式、表格、提醒块等元素。
2. 先梳理整体标题层级，再处理局部格式，避免层级跳跃。
3. 按 `frontmatter → 标题 → 按钮/窗口 → 图片 → 表格 → 公式 → 提醒块 → 引用 → 空行/加粗 → 引号` 处理。
4. 修改后按验证清单自检；若用户要求验证，或修改涉及公式、链接、构建风险，再运行构建或相关检查。

## 格式规则

### Frontmatter

- 保留已有字段，不随意删除或重排重要字段；不主动新增 `title`，已有 `title` 保留。
- 缺少 `description` 时，根据核心内容补充 20-50 字简洁描述；已有描述过长、空泛或不准确时可压缩为准确简洁版本。

### 标题与层级

- 页面主标题 `#` 应紧跟 frontmatter；`PathViewer` 等页面组件通常放在主标题之后。
- 移除标题前编号，如 `1.`、`1.1`、`一、`、`（1）`、`1）`；标题末尾不要标点。
- 标题层级连续，不从 `#` 跳到 `###`；并列内容层级一致，案例教程正文通常只使用 `#` 和 `##`。
- 标题简洁保留原意；原标题含说明句时，将说明句下移为正文。
- 不要为了消除编号而把每个操作小节机械提升为 Markdown 标题。
- 在轨道机动规划工具案例中，`##` 通常用于“创建任务场景”“插入卫星”“定义初始轨道参数”“设置预报段”“机动进入……”“运行任务控制序列”等主流程阶段。
- 主流程阶段内部的“定义瞄准序列段”“选择变量”“设置瞄准器”“运行结果显示”等阶段性条目，可保留为编号列表加粗项，如 `1. **定义瞄准序列段**`，其下内容按列表缩进组织。
- 当某个编号列表项是同一 `##` 或 `###` 章节下的并列阶段，且其后包含多个操作步骤、表格或图片，应写成加粗列表标题，如 `1. **遍历分析**`、`2. **优化分析**`、`3. **控制偏差预报**`。
- 碰撞规避、覆盖分析、批量处理等案例中，“设置条件约束”“高级设置”“载入到机动复核”“结果展示”“查看结果与存储”等短语若统领后续多条缩进内容，优先保留为编号加粗列表项，而不是普通列表项或 Markdown 标题。
- “轨道预报器设置”“停止条件设置”等局部配置步骤通常保持普通编号列表项，不要仅因其后包含说明、列表或表格就自动加粗；只有它们与相邻阶段并列并统领多步内容时才加粗。
- 只有当某个短语与相邻 `##` 章节同级、统领较长独立内容，或原文已形成稳定同级章节时，才改为 Markdown 标题。
- 列表项形如“短标题。后续正文”，且短标题是阶段性条目并统领后续段落、图片或表格时，拆为列表项加粗标题和缩进正文；若只是普通一步操作或局部配置说明，保留普通编号列表项。
- 避免使用 `####` 及更低级标题；需要更细结构时优先用编号列表、加粗列表项和缩进块表达。

### 按钮、控件、窗口

- 具体可点击按钮、菜单项、工具栏控件使用 `<kbd>`；标题、表头、列表项标题中的按钮名称不使用 `<kbd>`。
- 图标按钮若已有行内图标，按钮文字仍可用 `<kbd>`。
- 具体窗口、对话框、页面、面板、选项卡名称用中文方括号【】；通用词“窗口”“对话框”“页面”“面板”本身不包裹；已正确使用【】的内容保持不变。

### 图片与图标

- 独立图片使用 `![描述](路径)`，前后各保留一个空行。
- 独立图片位于列表项内时，按该列表项正文缩进，不要顶格脱离当前步骤。
- 与文字混排的小图标使用 `<img src="..." alt="..." no-view />`，必须包含 `no-view`。
- 不修改图片路径；除非用户明确要求，不重命名图片文件。

### 段落、列表、空行、加粗

- 段落、标题、图片、代码块、表格、提醒块之间保留一个空行，不连续堆叠多个空行。
- 列表项之间加空行；列表项内段落、图片、提醒块、代码块等块级元素保持与正文一致缩进。
- 中英文、数字、代码、快捷键之间的空格按原文风格保持一致，除非明显影响可读性。
- 加粗标记前后与中文正文之间保留空格，紧邻标点时不强制加空格。
- 编号列表项作为阶段标题时，整项短标题加粗：`1. **阶段名称**`；不要写成 `1. 阶段名称` 后直接缩进多段内容。
- 不把普通强调内容提升为标题，除非它统领后续结构。

### 表格

- 多列表格保留表格结构，只规范空格、表头和对齐线。
- 单列表格若只是罗列内容，转换为列表或普通段落。
- 不改动表格数据、单位、数值精度和顺序。

### 公式

- 块级公式使用 `$$ ... $$`，行内公式使用 `$ ... $`。
- 将 `\[ ... \]` 转为 `$$ ... $$`，将 `\( ... \)` 转为 `$ ... $`。
- 不修改公式含义、变量、上下标、单位和编号。

### 提醒块与折叠块

- 提示、注意、警告、重要说明等内容转换为 VuePress 容器并补简洁标题；普通引用若表达提示、注意或警告，也转换为提醒块并移除 `>`。
- 已规范的 VuePress 容器不重复转换，只在缺少标题时补简洁标题。
- `:::` 容器前后各保留一个空行，与相邻正文、公式、代码块等元素明确分隔；容器内部起始和结束处不额外加空行。
- 提醒块位于列表项内时，`:::` 起止行和内容行都按列表项正文缩进，避免脱离当前步骤。
- 容器映射：提示/Tip → `::: tip`；注意/Note、警告/Warning → `::: warning`；重要/Important → `::: important`；谨慎/Caution → `::: caution`。
- 仅当长参数说明、长步骤说明或附录内容影响主流程阅读时使用 `::: details 标题` 折叠块，不为统一格式滥用。

### 引用与参考文献

- **仅当参考文献条目本身是链接（URL）时**，才将正文中的 `[n]` 角标式引用转换为内联 Markdown 链接，用被标注词语作为链接文本：`[安装](https://example.com)并运行`。
- 如果参考文献条目是纯文本（如没有 URL 的学术论文、书籍、报告等），不转换为内联链接，保留原文的 `[n]` 角标和 `## 参考文献` 章节不变。
- 转换后在文末查找对应的 `## 参考文献` 章节，移除已内联的条目；若该章节所有条目均已内联，删除整个 `## 参考文献` 章节。
- 不要机械地将所有 `[数字]` 模式替换为链接；仅处理对应 `## 参考文献` 中实际列出的引用条目，且仅当该条目包含 URL 时才转换为链接。

### 中文引号

- 中文自然语言中的双引号使用中文弯引号：左引号 `“`（U+201C）、右引号 `”`（U+201D）。
- 代码、路径、命令、JSON、YAML、HTML 属性、英文参数中的双引号保持直引号 `"`（U+0022）。
- 不确定上下文时，优先保护代码和路径，不做机械全局替换。
- 修改中文引号后检查方向：`“文本”` 正确，`”文本“` 错误。

## 常用转换示例

```markdown
# 1. 创建场景

1. 运行 ATK.exe，点击"新建一个想定文件"；
2. 打开新建向导对话框，设置场景名称为 CoverageExample；
**注意**：使用前请备份文件。
```

转换为：

```markdown
# 创建场景

1. 运行 ATK.exe，点击 <kbd>新建一个想定文件</kbd>。

2. 打开【新建向导】对话框，设置 **场景名称** 为 **CoverageExample**。

::: warning 使用前注意
使用前请备份文件。
:::
```

其他示例规则：`点击 新建 按钮` → `点击 <kbd>新建</kbd> 按钮`；`打开新建向导对话框` → `打开【新建向导】对话框`；`1. 遍历分析` 后接多条缩进步骤 → `1. **遍历分析**`；`\[ E = mc^2 \]` → `$$ E = mc^2 $$`；`行内公式 \( a^2 \)` → `行内公式 $ a^2 $`；`安装[1]并运行 ATK.exe` + 文末 `[1] https://...`（参考文献条目为链接）→ `[安装](https://...)并运行 ATK.exe`，并移除 `## 参考文献` 章节；`参见文献[2]` + 文末 `[2] 某某论文，期刊名，2020`（参考文献条目为纯文本无链接）→ 保持原样不变。

## 边界情况

- 标题中的按钮名称不加 `<kbd>`；表格、图片、公式中的数据和路径不改。
- 普通操作步骤不改成标题；非提示性质的普通引用可保留 `>`。
- 列表项内已有规范的图片、提醒块、代码块等块级内容，只修正缩进和空行，不改变其归属步骤。
- 涉及链接路径、图片路径、公式兼容性的大范围修复时，先征求用户确认或改用专项检查。

## 验证清单

完成后检查：

- [ ] Frontmatter 有准确、简洁的 `description`。
- [ ] 页面主标题位于 frontmatter 后，`PathViewer` 等页面组件不抢在主标题前。
- [ ] 标题无编号、无末尾标点，层级连续，并列一致，不超过必要深度。
- [ ] 主流程阶段使用标题，阶段内部统领多步内容的阶段性条目使用编号加粗列表，普通配置步骤未误加粗或误升为标题。
- [ ] 操作按钮使用 `<kbd>`，标题、表头、列表项标题未误用 `<kbd>`。
- [ ] 具体窗口、对话框、页面、面板名称使用【】。
- [ ] 独立图片前后有空行，行内图标使用 `<img ... no-view />`。
- [ ] 列表项内图片、提醒块、代码块等块级元素缩进正确，未脱离所属步骤。
- [ ] 段落、列表、代码块、表格、提醒块之间空行合理，无连续多余空行。
- [ ] 单列表格已按语义转为列表或段落，多列表格数据未改动。
- [ ] 块级公式为 `$$`，行内公式为 `$`。
- [ ] 提示、注意、警告等内容使用合适的 `:::` 容器并带标题，容器前后各有一个空行。
- [ ] 中文弯引号方向正确，代码和路径中的直引号未被误改。
- [ ] `[n]` 角标引用中，参考文献条目为链接的已转为内联 Markdown 链接并移除对应条目；纯文本参考文献（无 URL）保持原样不变。
- [ ] 未改动用户未要求修改的链接、图片路径、数值和技术结论。
