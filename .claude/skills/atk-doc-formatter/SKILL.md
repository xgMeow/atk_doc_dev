# ATK 文档结构格式化工具

## 何时使用

当用户提出以下任一请求时，应激活此 skill：

- “请格式化这篇文档”
- “按规范整理这个 Markdown 文件”
- “优化文档结构，使其更易读”
- 用户提供 Markdown 文档并期望统一的格式风格（特别是包含 ATK 软件操作步骤的文档）
- 文档中存在格式混乱：标题带编号、按钮未标记、对话框名称未用【】、公式格式不统一等

## 核心原则

在执行任何格式化操作前，始终牢记：

1. **只改格式，不改内容**：原文意思完整保留
2. **不私自改链接**：所有原有链接保持原样
3. **不私自改表达**：用户原始描述方式保留，只优化结构
4. **不进行内容拓展**：不添加原文档中没有的信息

## 格式化指令

按以下顺序处理文档。每一条规则都给出了“原格式 → 目标格式”的明确转换方式。

### 1. 标题（Headings）

- 移除标题前的编号（如 `1.`、`一、`、`1.1`）
- 标题层级不可跳级（例如 `#` 后必须是 `##`，不能直接 `###`）

**转换示例**：
```markdown
# 1. 创建任务场景   →   # 创建任务场景
### 三级标题（前面缺少##） → 需补充 ## 二级标题，再保留 ### 三级标题
```

### 2. 按钮（Buttons）

- **操作按钮**：用 `<kbd>` 标签包裹按钮文字
- **例外**：按钮作为标题或列表项标题时，**不**使用 `<kbd>`

**转换对照**：

```markdown
点击 新建 按钮   →   点击 <kbd>新建</kbd> 按钮
## 新建（作为标题）   →   保持不变（无kbd）
1. 添加卫星（列表项标题）   →   保持不变（无kbd）
在【开始】栏点击 插入   →   在【开始】栏点击 <kbd>插入</kbd>
```

### 3. 窗口与对话框（Windows/Dialogs）

- 具体的窗口、对话框、页面名称用【】包裹
- 通用的“对话框”、“窗口”等词汇不处理

**转换对照**：
```markdown
打开新建向导对话框   →   打开【新建向导】对话框
在属性窗口中   →   在【属性】窗口中
查看覆盖分析报告页面   →   查看【覆盖分析报告】页面
```

### 4. 图片（Images）

- **独立图片**：单独占一行的图片，统一使用 `![描述](路径)` 格式。
- **行内小图标**：与文字混排的小图标，统一使用 `<img src="..." no-view />` 格式。
- **空行要求**：独立图片的前后必须各有一个空行（与相邻段落、列表、代码块等隔离）。

**转换示例**：

```markdown
上一段文字（段落结尾）

![覆盖时段分析报告](./media/image30.png)

下一段文字（段落开头）
```

**行内图标示例**：

```markdown
点击 <img src="./media/add.png" alt="新增" no-view /> 可添加新项。
```

### 5. 段落与空行

- 段与段之间必须有空行，且只空一行
- 列表项之间不需要空行

### 6. 表格（Tables）

- 只有一列的表格 → 取消表格的结构，转换为文字描述的形式
- 多列表格 → 保留原表格结构

### 7. 加粗（Bold）

- 加粗文字前后必须有空格（除非紧贴标点符号）

**正确**：`这是 **粗体** 文字` 
**错误**：`这是**粗体**文字`

### 8. 公式（Formulas）

- 块级公式：`\[ ... \]` → `$$ ... $$`
- 行内公式：`\( ... \)` → `$ ... $`

**转换示例**：
```markdown
\[ E = mc^2 \]   →   $$ E = mc^2 $$
行内公式 \( a^2 \)   →   行内公式 $ a^2 $
```

### 9. 提醒块（Callouts）

将文档中的提示、注意、警告等关键信息转换为 `:::` 格式的提醒块，并根据内容补充恰当的标题。

**何时转换**：
- 原文包含以下关键词（或英文对应词）时，必须转换
- 原文使用普通引用（`>`）但内容属于提示/注意/警告等类型时，也应转换为提醒块，并移除 `>`

**关键词与提醒块类型对照**：

| 原文关键词                  | 目标格式        | 建议标题（根据内容归纳） |
| --------------------------- | --------------- | ------------------------ |
| **提示**：、**Tip**：       | `::: tip`       | 例如：“使用前准备”       |
| **注意**：、**Note**：      | `::: warning`   | 例如：“注意事项”         |
| **警告**：、**Warning**：   | `::: warning`   | 例如：“警告”             |
| **重要**：、**Important**： | `::: important` | 例如：“重要说明”         |
| **谨慎**：、**Caution**：   | `::: caution`   | 例如：“谨慎操作”         |

**转换示例 1（关键词转换）**：

```markdown
**注意**：使用前请先保存文件。
→
::: warning 使用前注意
使用前请先保存文件。
:::
```

**转换示例 2（普通引用转换）**：

```markdown
> 提示：网格检查前请确保已完成覆盖计算。
→
::: tip 使用网格检查工具的前提
网格检查前请确保已完成覆盖计算。
:::
```

**补充标题规则**：
- 如果原文已有 `:::` 提醒块但没有标题，根据内容补上一个简洁的标题
- 标题应概括该提醒的核心内容（如“注意事项”、“操作前确认”等）

### 10. 折叠块（Details）

当多步操作或长参数列表需要分组时，使用：

```markdown
::: details 标题（如“展开查看完整配置”）
折叠的内容
:::
```

### 11. 引号规范化（Quotation Mark Normalization）

**目标**：根据上下文，将文档中的双引号转换为正确形式：

- **中文文本**：使用成对的中文弯引号。**左引号（开）**：`”`（U+201C, LEFT DOUBLE QUOTATION MARK），**右引号（闭）**：`”`（U+201D, RIGHT DOUBLE QUOTATION MARK）。左右方向一定不能搞反。
- **代码、路径、命令行参数、英文专用术语**：保持直双引号 `”`（U+0022, QUOTATION MARK），不区分左右。

> 关键记忆：左引号 U+201C（`”`）开口朝右，右引号 U+201D（`”`）开口朝左。中文引号成对使用时，左引号在前、右引号在后：`”中文”`。

**每次修改涉及中文引号后，必须用 hex 自检**：

```bash
# 检查文件中是否误用了 U+0022（直引号）替代中文弯引号，
# 或左右引号方向是否写反。正确的中文引号只应出现：
#   e2 80 9c = U+201C = “（左）
#   e2 80 9d = U+201D = “（右）
# 而不应出现：
#   22 = U+0022 = “（直引号，仅代码/路径中允许）
grep -nP '[\x{201c}\x{201d}\x{0022}]' <文件> | head -20
```

**参考复制行**（可直接从此处复制正确的引号对用于 Edit）：

```
左引号：” (U+201C)
右引号：” (U+201D)
中文示例：”文本”
```

**转换示例**：

```markdown
# 原文（中文内容使用了直双引号）
参数值为 “测试”
→ 参数值为 “测试”

# 原文（中文内容使用了反向弯引号）
用户说：”你好”。
→ 用户说：”你好”。

# 原文（代码中的直双引号保持不变）
print(“hello”)
→ print(“hello”)

# 原文（文件路径中的直双引号）
--config=”C:\config.json”
→ --config=”C:\config.json”

# 原文（缺失左引号，不成对）
用户说：你好”
→ 用户说：”你好”
```

### 12. 文档描述（Description）

- 若文档 frontmatter 中缺少 `description` 字段，根据文档内容补充一个简洁的描述
- 描述应概括文档的核心内容，长度控制在 20-50 字
- 若已有 `description` 但描述不准确或过长的，优化为简洁版本
- 不用添加 `title` 字段

**转换示例**：
```markdown
---
title: 入门案例
---
→
---
title: 入门案例
description: 通过创建简单覆盖分析任务，快速上手 ATK 的基本操作流程。
---
```

## 完整工作流程

### 第1步：理解原文
- 完整阅读用户提供的文档
- 识别文档类型（案例教程、帮助文档、理论基础等）
- 确认是否有特殊要求

### 第2步：逐步格式化
按顺序应用上述13条规则（标题 → 按钮 → 窗口/对话框 → 图片 → 段落与空行 → 表格 → 加粗 → 公式 → 提醒块 → 折叠块 → 引号规范化 → 文档描述）。 
每应用一条规则，确保不破坏已有内容。

### 第3步：内容核对
- 逐段对比原文与格式化后的结果
- 确认没有遗漏、错改或添加内容

### 第4步：结构优化（可选）
- 如果文档较长，可添加内部的 Markdown 锚点链接（如 `[跳转](#标题)`）
- 为独立操作步骤增加折叠分组
- 确保提醒块放置在相关段落之前或之后，逻辑连贯

## 示例演示

### 示例1：操作步骤+按钮+对话框

**输入**：
```markdown
# 1. 创建场景

1. 运行 ATK.exe，点击"新建一个想定文件"；
2. 打开新建向导对话框，设置场景名称为 CoverageExample；
```

**输出**：
```markdown
# 创建场景

1. 运行 ATK.exe，点击 <kbd>新建一个想定文件</kbd>

2. 在【新建向导】对话框中，设置 **场景名称** 为 **CoverageExample**
```

### 示例2：单列表格转换 + 加粗空格

**输入**：
```markdown
| 数值 |
| ---- |
| 500  |

设置**高度**为500。
```

**输出**：
```markdown
- 数值：500

设置 **高度** 为500。
```

### 示例3：公式与提醒块

**输入**：
```markdown
计算公式为 \[ a^2 + b^2 = c^2 \]。
**注意**：使用前请备份文件。
```

**输出**：
```markdown
计算公式为 $$ a^2 + b^2 = c^2 $$。

::: warning 使用前注意
使用前请备份文件。
:::
```

## 边界情况与注意事项

- **标题中带有按钮**：不添加 `<kbd>`，保持原文字（例如 `## 新建`）
- **列表项中既有标题又有操作**：列表项开头的文字（作为该项标题）不加 `<kbd>`；描述中的具体按钮加 `<kbd>`。
- **空行**：注意不要引入多余空行（如列表项之间不需要空行，但段落之间必须有空行且只有一个空行）。
- **引号**：中文引号是最高频的格式错误。左引号为 U+201C（`"`），右引号为 U+201D（`"`）。两者在等宽字体中肉眼难以区分，写完引号后务必用 `xxd` 或 hex 工具验证字节是否正确。**在 Edit 工具的输入框中，你打出的 `"` 和 `"` 可能被编辑器自动转换，导致实际写入文件的字符并非你预期的那一个——只有 hex 能告诉你真相。**

## 验证清单

格式化完成后，用以下清单自检：

- [ ] 所有标题无编号，层级连续
- [ ] 操作按钮有 `<kbd>`，标题中的按钮无 `<kbd>`
- [ ] 具体窗口/对话框/页面名称有【】
- [ ] 块级公式为 `$$`，行内公式为 `$`
- [ ] 图片前后有空行
- [ ] 段落之间有空行，代码块前后有空行
- [ ] 没有单列表格
- [ ] 加粗文字前后有空格（除非紧邻标点）
- [ ] 提示/注意等语句已转换为 `:::` 块，且带有标题
- [ ] 中文弯引号：左 `”`（U+201C）右 `”`（U+201D）方向正确，已用 hex 验证而非肉眼判断
- [ ] 文档 frontmatter 有 `description`，内容简洁准确（20-50字）
