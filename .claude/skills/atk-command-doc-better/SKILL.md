# ATK CONNECT 命令文档格式化

将 ATK 二次开发 CONNECT 命令库中的命令参考文档统一为标准格式，使结构清晰、章节完整、风格一致。

## 何时使用

当用户要求规范化、格式化、整理 CONNECT 命令库中的单个命令文档（`场景/` 目录下的 `.md` 文件），或要求将某篇命令文档改为"标准格式"、"参考格式"时使用。

不要用于：批量处理场景目录以外的文档、重写文案内容、修改命令语法本身、处理 README.md 等目录索引文件。

## 目标格式

每篇命令文档由以下五个标准章节组成，按顺序排列：

```
# <命令名>

## 作用

<一句话或一段话描述该命令的核心功能>

## 语法

```（无语言标记）
<命令语法，使用尖括号和花括号标注参数>
```

## 参数说明

| 参数 | 说明 |
|------|------|
| `<参数名>` | <参数描述> |

（可选）### <参数取值子表> — 当参数有枚举值/固定取值时使用

## 补充说明

- <使用场景、注意事项、相关命令引用等>

## 示例

::: details open **<描述该示例做什么>**

```（无语言标记）
<完整可执行的命令示例>
```

:::
```

## 各章节规范

### 标题（`#`）

- 一级标题即为命令名称，不添加编号、后缀或修饰语。
- 命令名使用原文中的精确写法（大小写、下划线、空格保持一致）。

### 作用（`## 作用`）

- 用一句话概括命令的核心功能。
- 使用**加粗**突出关键术语（如 **一对一**、**批量**、**配置步骤**、**执行步骤**）。
- 仅一个段落，不展开细节。

### 语法（`## 语法`）

- 使用无语言标记的代码块（` ``` ` 不加语言标识）。
- 角括号 `<参数>` 表示必填参数，花括号 `{参数组}` 表示可选参数组或互斥参数组。
- 省略号 `…` 表示可指定多个同类参数。
- 管道式 `/` 分隔表示命令层级（如 `AccessMulti / Access Compute`）。

### 参数说明（`## 参数说明`）

- 使用两列表格：`参数 | 说明`。
- 参数名列使用反引号包裹（如 `` `<ObjectPath>` ``）。
- 参数说明简洁，必要时用 `<br/>` 在单元格内换行补充子参数说明。
- 若参数为枚举值（如 `<ReportStyle>`），在下方新增 `### <参数名> 取值` 子表，列出所有可选值及含义。

### 补充说明（`## 补充说明`）

- 使用无序列表（`-`）。
- 内容包括但不限于：
  - 该命令适用于什么场景（**一对一**、**批量处理**、**先配置后计算** 等）。
  - 该命令在整个命令族中的角色（**配置步骤**、**执行步骤** 等）。
  - 与其他相关命令的配合使用关系，用反引号引用命令名（如 `AccessMulti / Assets`）。
  - 替代方案的说明（"如果需要 X，可以改用 `Y` 命令"）。
- 关键概念和角色标注使用加粗。

### 示例（`## 示例`）

- 每个示例用一个 `::: details open **描述**` 折叠容器包裹。
- `open` 表示默认展开；描述文本加粗，概括示例的操作场景。
- 容器内放代码块（无语言标记），内容是可直接复制使用的完整命令。
- 如有多个示例，依次并列多个 `::: details` 容器。

## 工作流程

1. 阅读目标文档，理解命令功能、参数和用法。
2. 识别原文中已有的章节，将其内容映射到标准五章节结构：
   - `用法` → `语法`
   - `说明` → `参数说明`（表格化）或 `补充说明`（列表化）
   - `举例` → `示例`
3. 按标准格式重写，保留原文中所有信息（命令语法、参数说明、示例数据、时间戳）。
4. 补充缺失章节：
   - 无"作用"时根据命令功能归纳一句话。
   - 无"补充说明"时根据参数和用法归纳使用场景和关联命令。
   - 示例无折叠容器时补上 `::: details` 和描述文本。
5. 修改后对照规范清单自检。

## 验证清单

完成后检查：

- [ ] 文档有且仅有五个标准章节：`作用`、`语法`、`参数说明`、`补充说明`、`示例`。
- [ ] 标题为命令名，无编号无后缀。
- [ ] 语法使用无语言标记的代码块，参数使用 `<>` 或 `{}` 标注。
- [ ] 参数说明为两列表格（参数/说明），参数名有反引号包裹。
- [ ] 若有枚举参数，已添加取值子表。
- [ ] 补充说明使用无序列表，关键术语加粗，相关命令用反引号引用。
- [ ] 示例使用 `::: details open **描述**` 折叠容器，内部为完整可执行命令。
- [ ] 章节之间由空行分隔。
- [ ] 未改动用户未要求修改的命令语法、参数值、示例时间戳等数据。

## 常见转换映射

| 原文章节 | 目标章节 | 处理方式 |
|----------|----------|----------|
| `用法` | `语法` | 直接迁移，统一代码块格式 |
| `说明`（表格） | `参数说明` | 迁移为参数/说明两列表格 |
| `说明`（列表/段落） | `补充说明` | 迁移为无序列表 |
| `举例` | `示例` | 补加 `::: details` 折叠容器和描述 |
| 无"作用" | `作用` | 根据文档内容归纳一句 |
| 无"补充说明" | `补充说明` | 根据参数和功能归纳场景和关联 |

## 边界情况

- 原文有 frontmatter 时保留并移至文件顶部，`#` 标题紧跟其后。
- 原文中与其他命令的参见链接（如 `[Access](../Access.md)`）保留在补充说明中，不删除。
- 原示例中时间戳、对象路径等数据一字不改，仅调整外围容器格式。
- 原文已有的 VuePress 容器（`::: tip`、`::: warning` 等）保留，不额外包裹。
- 如有多个命令变体共用一个文档，仅保留主命令格式，不拆分文件。
