# ATK 文档优化规范

## 优化目标

当用户说「检查文档」「优化结构」「优化文档」「整理文档」时，严格按以下规范执行。只改结构，不改内容，不要拓展。

## 格式规范

### 标题
- 标题不编号

### 按钮与对话框
- 按钮用 `<kbd>按钮名</kbd>` 格式，如 `<kbd>插入</kbd>`、`<kbd>新建</kbd>`（按钮作为标题时除外）
- 按钮作为标题时使用 `【按钮名】` 格式，如 `【插入】`、`【新建】`
- 打开对话框格式：`【XXX】对话框`，如 `【插入】对话框`

### 文字与段落
- 加粗格式为 `**XXX**`，内容与星号之间不要有空格；加粗文字与前后文字之间要有空格，如 `XX **XXX** XX`，而非 `XX**XXX**XX`
- 段与段之间必须有空行

### 表格
- 只有一列时不用表格，改用列表或引用格式

### 图片
- 单独一行的图片：`![描述](路径)`，图片前后空行
- 行内图标图片：`<img src="./media/xxx.png" no-view>`
- 图片不加序号

## 语病检查

### 常见语病类型及修正
- **重复啰嗦**：删除冗余表述，如"进行一个修改" → "修改"
- **搭配不当**：修正词语搭配，如"提高水平"而非"增强水平"
- **成分残缺**：补充缺失成分，如"通过学习，使我..." → "通过学习，我..."
- **语序不当**：调整词语顺序，如"认真地仔细检查" → "仔细检查"
- **语义重复**：消除重复语义，如"非常十分重要" → "十分重要"
- **指代不明**：明确指代对象，如"它的性能很好" → "该设备的性能很好"

### 专业术语规范
- 保持术语一致性，如全程统一使用"卫星"或"航天器"
- 专业名词拼写正确，如"LVLH"、"GCRF"、"ICRF"等缩写首次出现需注明全称

## 结构优化

尽可能使用多样的markdown样式，例如使用以下 Markdown 语法增强结构：

### 折叠
```
::: details 标题
内容
:::
```

### 提示块
```
> [!TIP]
> 提示内容

> [!WARNING]
> 警告内容

> [!NOTE]
> 注意内容
```

### 引用
```
> 引用内容
```

### 表格
复杂数据用表格展示

## 禁止事项

- **不要**改链接
- **不要**改表达的意思
- **不要**拓展内容
- **不要**改图片路径
- **不要**私自调整链接跳转

## 执行流程

按照以下顺序严格执行检查和修正：

1. **标题检查**：遍历所有 `#` 标题，检查并移除数字编号
2. **按钮与对话框检查**：搜索所有按钮内容，正文描述中修正为 `<kbd>按钮名</kbd>` 格式，按钮作为标题时使用 `【按钮名】` 格式
3. **加粗格式检查**：检查所有 `**` 加粗内容，确保格式正确
4. **段落格式检查**：检查段落之间是否有空行
5. **表格检查**：检查单列表格并转换为列表/引用
6. **图片格式检查**：检查图片前后空行和序号标注
7. **公式检查**：检查公式格式，将 `\[ \]` 格式转换为 `$$ $$`，确保行内公式使用 `$ $` 格式
8. **语病检查**：检查并修正常见语病
9. **专业术语检查**：确保术语一致性和正确拼写

## 执行原则

- **完整性**：必须检查并修正所有检查项，不得遗漏
- **准确性**：严格按照修正方法执行，确保格式正确
- **内容保护**：只修改格式，不改变内容含义
- **可追溯性**：每个修改都应有明确的检查项对应
