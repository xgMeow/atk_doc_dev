# Basic Constraints

## 1. Functional Description

Basic Constraints are used to filter visibility intervals, communication intervals, or coverage intervals based on the relative geometric relationship between the analysis object and associated objects. By setting geometric conditions such as azimuth angle, elevation angle, range, angular rate, altitude, and propagation delay, combined with line‑of‑sight, field‑of‑view, and terrain occlusion judgments, it can be determined whether two objects satisfy mission requirements at the current time.

Basic Constraints mainly include the following four categories:

| Constraint Type | Function |
| --- | --- |
| Geometric Parameter Constraints | Judge the relative geometry between objects based on parameters such as azimuth, elevation, range and their rates, angular rate, altitude, and propagation delay. |
| Line‑of‑Sight Constraint | Determines whether the line of sight between the analysis object and the associated object is obstructed by the central body. |
| Field‑of‑View Constraint | Determines whether the associated object lies within the sensor's effective field of view. |
| Terrain Constraint | Determines whether the line of sight between objects is obstructed by terrain elevation. |

Each constraint is independent. A given instant is considered to satisfy the Basic Constraints only when all enabled constraints are satisfied simultaneously.

---

## 2. Parameter Descriptions

| Parameter | Meaning |
| --- | --- |
| Azimuth Angle | The horizontal direction angle of the associated object relative to the analysis object, describing the horizontal bearing of the associated object. |
| Elevation Angle | The angle between the line of sight from the analysis object to the associated object and the reference plane, describing the vertical direction of the associated object relative to the analysis object. |
| Range | The straight‑line distance between the analysis object and the associated object. |
| Azimuth Rate | The time rate of change of the azimuth angle, reflecting the target's rotational speed in the reference plane. |
| Elevation Rate | The time rate of change of the elevation angle, reflecting the target's angular motion speed in the vertical direction. |
| Range Rate | The time rate of change of the distance between two objects. A positive value indicates the objects are moving apart, while a negative value indicates they are approaching. |
| Angular Rate | The rotational speed of the line‑of‑sight direction from the analysis object to the associated object, which can be used to assess tracking capability and communication link stability. |
| Altitude | The height of an object above the reference surface of the central body. |
| Propagation Delay | The time required for information or signals to propagate between the analysis object and the associated object. |
| Line‑of‑Sight Constraint | Determines whether the line between objects is obstructed by the Earth or other central bodies. |
| Field‑of‑View Constraint | Determines whether the target direction lies within the sensor's specified field‑of‑view angles. |
| Terrain Constraint | Determines whether the line of sight between objects is obstructed by actual terrain. |

For geometric parameters with both minimum and maximum values, the lower and upper bounds can be enabled independently. When both are enabled, the parameter $x$ must satisfy:

$$
x_{\min}\leq x\leq x_{\max}
$$

## 3. Geometric Parameter Constraints

Geometric parameters include Azimuth ($Az$), Elevation ($El$), Range ($R$) and their rates, as well as Angular Rate, Altitude, and Propagation Delay.

### 3.1 AER and Their Rates

Azimuth, elevation, and range characterize the spatial bearing and distance of the associated object relative to the analysis object.

Let $\boldsymbol r$ be the position vector of the associated object relative to the analysis object, and let $r_x$, $r_y$, $r_z$ be the components of the relative position along the $OX$, $OY$, and $OZ$ axes. The geometric relationship is shown in the figure below.

![Azimuth and Elevation Definition](../../../../zh/5.专业使用指南/01-可见性与覆盖分析/05-约束配置/media/基本约束/image1.png)

The formulas for azimuth, elevation, and range are respectively:

$$
Az
=
\operatorname{arctan2}
\left(
r_y,r_x
\right)
$$

$$
El
=
\arctan
\left(
\frac{r_z}
{\sqrt{r_x^2+r_y^2}}
\right)
$$

$$
R
=
\sqrt{
r_x^2+r_y^2+r_z^2
}
$$

Let $\boldsymbol v$ be the velocity vector of the associated object relative to the analysis object, and let $v_x$, $v_y$, $v_z$ be its three components. The azimuth rate is:

$$
\frac{\mathrm dAz}{\mathrm dt}
=
\frac{
r_xv_y-r_yv_x
}{
r_x^2+r_y^2
}
$$

The elevation rate is:

$$
\frac{\mathrm dEl}{\mathrm dt}
=
\frac{
-v_z+\dfrac{r_z}{\boldsymbol r\cdot\boldsymbol v}
}{
\sqrt{
(R-r_z)(R+r_z)
}
}
$$

The range rate is:

$$
\frac{\mathrm dR}{\mathrm dt}
=
\frac{
r_x\omega_x+r_y\omega_y+r_z\omega_z
}{
R
}
$$

where:

$$
\boldsymbol\omega
=
\boldsymbol v
-
\boldsymbol\omega_{\mathrm{orb}}
\times
\boldsymbol v
$$

$$
\boldsymbol\omega_{\mathrm{orb}}
=
\frac{
\boldsymbol r\times\boldsymbol v
}{
R^2
}
$$

Here, $\boldsymbol\omega_{\mathrm{orb}}$ is the orbital angular velocity vector of the analysis object.

The reference coordinate system used for the relative position vector $\boldsymbol r$ depends on the type of analysis object. For fixed ground objects, $\boldsymbol r$ is defined in the object's local LH (Local Horizontal) coordinate system. For ground mobile objects, $\boldsymbol r$ is defined in the VVLH (Vehicle Velocity Local Horizontal) coordinate system based on the Central Body Fixed (CBF) frame. For space mobile objects, $\boldsymbol r$ is defined in the VVLH coordinate system based on the Central Body Inertial (CBI) frame.

The correspondence between object types and reference coordinate systems is shown in the table below.

| Reference Coordinate System | Object Type |
|---|---|
| LH | Ground Station |
| CBF‑VVLH | Vehicle, Ship, Submarine, Aircraft |
| CBI‑VVLH | Satellite, Rocket, Missile |

For attached objects, the reference coordinate system is the same as that of their parent object.

### 3.2 Angular Rate

Angular rate characterizes the rotational speed of the associated object relative to the analysis object, computed as:

$$
val
=
\frac{
\left\|
\boldsymbol r\times\boldsymbol v
\right\|
}{
R^2
}
$$

In communication link analysis, angular rate can be used to characterize the stability of the link between two objects.

### 3.3 Altitude

Altitude characterizes the height constraint relative to the ground when the analysis object and the associated object establish a visible relationship. Both maximum and minimum values can be set. Altitude is computed as:

$$
h
=
R_{\mathrm{obj}}
-
R_{C,\mathrm{local}}
$$

where:

- $R_{\mathrm{obj}}$ is the geocentric distance of the analysis object in the LLR coordinate system;
- $R_{C,\mathrm{local}}$ is the local radius of the central body.

### 3.4 Propagation Delay

Propagation delay characterizes the time required to transmit information between the analysis object and the associated object, computed as:

$$
val
=
\frac{R}{v_{\mathrm{light}}}
$$

where:

$$
v_{\mathrm{light}}
=
299792458.0\ \mathrm{m/s}
$$

Here, $v_{\mathrm{light}}$ represents the speed of light.

## 4. Line‑of‑Sight Constraint

The line‑of‑sight constraint is primarily used to analyze cases where objects become invisible due to central body occlusion. This constraint evaluates the line‑of‑sight quality between two objects and characterizes the degree to which the central body obstructs the visibility relationship. The output value calculation method depends on the type of object to which the line‑of‑sight constraint belongs.

### 4.1 Fixed Objects

If the object to which the line‑of‑sight constraint belongs remains fixed in position in the reference coordinate system (e.g., ground stations and their attached sensors, radars, etc.), the output value is defined as:

$$
val
=
\cos\beta-\cos\alpha
$$

where the geometric relationship between $\alpha$ and $\beta$ is shown in the figure.

### 4.2 Mobile Objects

If the object to which the line‑of‑sight constraint belongs has motion attributes (e.g., satellites, aircraft, rockets, cars, ships, submarines, and their attached objects), the output value is defined as:

$$
val
=
R_C
\left(
\cos\beta-\cos\alpha
\right)
$$

where $R_C$ represents the semi‑major axis of the central body, applicable to tri‑axial ellipsoids, spheroids, and spheres.

![Line‑of‑Sight Constraint](../../../../zh/5.专业使用指南/01-可见性与覆盖分析/05-约束配置/media/基本约束/image2.png)

### 4.3 Simplified Calculation for Objects on the Celestial Body Surface

When the line‑of‑sight start or end point is located on the central body surface (i.e., the object elevation is $0$), the line‑of‑sight computation model can be simplified. The output value is then:

$$
val
=
\begin{cases}
\cos\gamma, & \text{Fixed Object} \\[4pt]
R_C\cos\gamma, & \text{Mobile Object}
\end{cases}
$$

where $\gamma$ is the geometric angle shown in the figure below.

![Simplified Line‑of‑Sight Calculation](../../../../zh/5.专业使用指南/01-可见性与覆盖分析/05-约束配置/media/基本约束/image3.png)

When an object has a negative elevation value, the central body model must be corrected so that the object lies on the surface of the corrected central body model, and the line‑of‑sight output value is then computed using the formulas above.

## 5. Field‑of‑View Constraint

The field‑of‑view constraint corresponds one‑to‑one with sensor objects and is used to determine whether the associated object lies within the sensor's effective observation range. The field‑of‑view range is defined by the sensor's characteristic angles.

The field‑of‑view constraint is satisfied only when the target direction lies inside the sensor's field of view.

---

## 6. Terrain Constraint

The terrain constraint accounts for the effect of terrain elevation on visibility and coverage. It determines whether the target is visible under the current geometry by assessing whether the line of sight between the objects is obstructed by terrain.

::: warning Terrain Data Configuration Notes
Before enabling **Terrain Constraint**, you should first configure the terrain data to be used in the analysis under [Scenario Object Properties → Terrain](../../../03-基础使用指南/02-场景管理/03-场景属性配置/02-基本/03-地形.md).

Note that the terrain data used for constraint computation and the terrain visualization in the 3D view are configured independently. Even if terrain is displayed in the 3D view, that terrain data may not be used for constraint computation.

If you need to display terrain effects in the 3D view, you must also configure the corresponding **visualization terrain data** in each **3D View**.
:::
