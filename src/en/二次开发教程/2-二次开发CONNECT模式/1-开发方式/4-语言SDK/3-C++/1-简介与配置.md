# Introduction and Configuration

## Introduction

The C++ SDK is the C++ communication library provided by ATK. It lets you write programs in your own C++ development environment and interact with ATK over a TCP network connection, enabling automated operations such as scenario building, parameter setting and simulation running.

As one of the core development methods in Connect mode, the C++ SDK provides header files (`.h`) and precompiled library files, which suits scenarios where you need to integrate ATK functionality into a C++ project or have high requirements for performance and low-level control.

| Platform | Static library | Dynamic library | Compiler requirements |
|------|--------|--------|-----------|
| Windows | `.lib` | `.dll` | Visual Studio 2015 / 2017 / 2019 / 2022 |
| Linux / Kylin | `.a` | `.so` | GCC 5.x and later |

::: tip Choosing a Development Method
For a detailed comparison of the development methods, refer to the [Connect Mode Overview](../../../README.md#development-method-comparison).
:::

## Environment and Configuration

### Compiler Requirements

- **Windows**: Visual Studio 2015 / 2017 / 2019 / 2022, with the **Desktop development with C++** workload installed; the platform toolset corresponds to v140 / v141 / v142 / v143
- **Linux**: GCC 5.x or later, with C++11 support

::: warning Note
Before sending commands with the C++ SDK, you must open the ATK software (no scenario needs to be open). To create a new scenario, close any scenario that is already open.
:::

### Header File Selection

Choose the corresponding header file according to the linking method:

- **Static library**: `#include "ATKConnectorlib.h"` — the library is compiled into the executable, so no additional dynamic library files need to be distributed
- **Dynamic library**: `#include "ATKConnectorDll.h"` — at runtime, the corresponding dynamic library file must be placed in the same directory as the executable (Windows: `.dll`; Linux: `.so`)

The APIs of the two approaches are identical. The example code uses the static library mode.

### Configuration Steps

#### Windows

1. According to the Visual Studio version installed on your computer, open the corresponding solution file:

| VS Version | Solution Directory | Platform Toolset |
|---------|-------------|-----------|
| VS 2015 | <PathCopy :entry="vs2015Sln" /> | v140 |
| VS 2017 | <PathCopy :entry="vs2017Sln" /> | v141 |
| VS 2019 | <PathCopy :entry="vs2019Sln" /> | v142 |
| VS 2022 | <PathCopy :entry="vs2022Sln" /> | v143 |

2. After opening the solution, Visual Studio prompts you to **retarget the project**; click OK to confirm it. (To configure manually: right-click the project → Properties → Configuration Properties → General, then select the installed versions for **Windows SDK Version** and **Platform Toolset**)

3. After the configuration changes are complete, select the **Release x64** configuration and press <kbd>Ctrl+Shift+B</kbd> to build it.

::: tip xmake Build (Optional)
You can also use the **xmake** cross-platform build tool instead of Visual Studio to compile:

```bash
xmake f -m release
xmake build
```
:::

#### Linux / Kylin

On Linux (Kylin), the C++ SDK is provided as precompiled libraries plus header files.

##### Directory Structure

```
C++/
├── include/                    # ATK connector public header directory
│   ├── ATKConnector.h
│   ├── ATKConnectorDll.h
│   └── ATKConnectorlib.h
├── lib/                        # Precompiled libraries for the Linux platform
│   ├── libATKConnectorDll.so    # Dynamic shared library
│   └── libATKConnectorlib.a     # Static archive library
├── qt/                         # Qt visualization test project directory
│   └── ConnectTest/
│       ├── ConnectTest.pro
│       └── main.cpp
├── src/                        # Native C++ business example source directory
│   └── ex-InclinationChange.cpp
└── README.md
```

##### GCC Compilation

In the command line, enter the C++ SDK root directory and compile the example code with GCC:

**Static linking (recommended)**:

```bash
g++ -std=c++11 -I./include -L./lib \
    src/ex-InclinationChange.cpp \
    -lATKConnectorlib \
    -o ex-InclinationChange
```

**Dynamic linking**:

```bash
g++ -std=c++11 -I./include -L./lib \
    src/ex-InclinationChange.cpp \
    -lATKConnectorDll \
    -o ex-InclinationChange
```

::: warning Note
When running with dynamic linking, make sure `libATKConnectorDll.so` is in the system library search path, or copy it to the same directory as the executable.
:::

After the build succeeds, run:

```bash
./ex-InclinationChange
```

##### Qt Project Compilation

If you develop with Qt Creator, you can refer to the Qt project under the `qt/ConnectTest/` directory:

```bash
cd qt/ConnectTest
qmake ConnectTest.pro
make
```

## Usage

After completing the configuration above, you can call the three core APIs in your code to control ATK. The basic flow is as follows:

```cpp
#include "ATKConnectorlib.h"

int main()
{
    // 1. Establish the connection to ATK
    int conID = atkOpen("127.0.0.1", 6655);

    // 2. Send a command (example: create a new scenario)
    atkConnect(conID, "New", "/ Scenario MyScenario");

    // 3. Close the connection
    atkClose(conID);

    return 0;
}
```

For detailed API parameter descriptions, see [Core API](./2-核心API.md); for a complete example, see [Complete Example](./3-完整示例.md).
