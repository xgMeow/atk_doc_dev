# Command Syntax Conventions

ATK CONNECT commands use the following symbols to indicate the type and constraints of parameters. Refer to this convention when reading command syntax.

## Basic Symbols

| Symbol | Meaning | Description |
|------|------|------|
| `<Parameter>` | Required parameter | Replace it with the actual value when using the command, e.g. `<ObjectPath>` → `*/Satellite/Satellite1`. |
| `[Parameter]` | Optional parameter | May be omitted as needed, e.g. `[WindowID <WinNumber>]` can be written or left out. |
| `{Option}` | Required choice | Must **select one** from the given options. For example, fill `{On \| Off}` with `On` or `Off`; fill `{Color}` in the color format. |
| `\|` | Option separator | Separates mutually exclusive options inside `{ }` and means "or", e.g. `{Details \| Platform}` is a choice of either one. |
| `"Text"` | String literal | Enter it as-is and **keep the double quotes**, e.g. `"<FilePath>"` → `"C:\data\file.a"`. |
| `...` | Repeatable | The preceding element may occur more than once, e.g. `({Option} <Value>)...` may hold several option-value pairs. |

## Path Symbols

| Symbol | Meaning | Description |
|------|------|------|
| `*` | Scenario wildcard | Represents the "current scenario", equivalent to `current scenario/`, e.g. `VO * CentralBody Mars` (where `*` is the current scenario). |
| `/` | Application path | Represents the current application, e.g. `AllInstanceNames /` lists all objects under the current application. |

## Path Parameters

The named path parameters that recur in commands have the following meanings.

| Parameter | Meaning | Description |
|------|------|------|
| `<ApplicationPath>` | Application path | The current application; fill in `/`. e.g. `UnloadSubObj / *`, `Copy / Satellite/Satellite1 Name Sat2`. |
| `<ScenarioPath>` | Scenario path | The scenario on which the command acts, usually filled in as `*` (the current scenario). e.g. `Animate * Start`, `Units_Get * GUI`. |
| `<ObjectPath>` | Full object path | Written in full starting from the scenario `*`, e.g. `*/Satellite/Satellite1`. |
| `<FacilityPath>` | Facility path | Path of the facility object on which the command acts, e.g. `*/Facility/Facility1`. |
| `<VehObjectPath>` | Vehicle path | Path of the vehicle object on which the command acts, covering aircraft, ships, GroundVehicles, satellites, missiles and LaunchVehicles, e.g. `*/GroundVehicle/GroundVehicle1`. |
| `<TruncObjPath>` | Truncated object path | Omits the scenario prefix `*/`, e.g. `Satellite/Satellite1`. |
| `<ClassPath>` | Object class path | The type of the object to be created, e.g. `Scenario`, `*/Satellite`. |
| `<AxesPath>` | Axes component path | The Axes component that the data refers to; it is a truncated path and must be enclosed in double quotes, e.g. `"CentralBody/Earth J2000.Axes"`. |

::: tip Full paths and truncated paths

`<ObjectPath>` is written in full starting from the scenario `*` and is a **full path**. Within one command, **the first group of paths is written as a full path** (starting with `*` or `/`), while **paths in all other positions are always written as truncated paths**, that is, with the scenario prefix `*/` omitted.

For example, in `Copy / Satellite/Satellite1 Name Sat2`, `/` is the first group of paths (the application path) and `Satellite/Satellite1` is the truncated path that follows it.
:::

## Common Rules

Commands follow the rules below when they are parsed.

**Keywords are case-insensitive**

Command names, subcommand names, option keywords and other **fixed words of the command itself are case-insensitive**. They are recognized whether written in all uppercase, all lowercase or camel case, with exactly the same effect. For example, the following three commands are equivalent:

```atk-command
Compute CAMEnum
COMPUTE camenum
compute camenum
```

**Types and names are case-sensitive**

Object types (such as `Satellite`, `Missile`, `Antenna`), object names and identifiers in paths **are case-sensitive** and must match the spelling used when the object was defined. For example, `*/Satellite/Satellite1` and `*/satellite/satellite1` are not equivalent.

**The number of spaces is not significant**

For any part not enclosed in double quotes, writing one space or several spaces between words is equivalent, and the command parses to the same result.

**Text inside double quotes is kept as-is**

Spaces inside double quotes belong to the string content itself and are not collapsed, so **only one space** may appear between words inside a string literal; an extra space produces a different string. For example, in the date and time `"1 Jul 2021 09:00:00.000"`, every segment must be separated by a single space.

## Additional Notes

- Commands separate words with **spaces**, and several consecutive spaces are equivalent to one; **spaces are not allowed** inside a parameter (except within a string literal).

- All parameter values are entered as **strings**; a numeric value is merely a string whose content is numeric. If a parameter value contains spaces (such as the date and time `"1 Jul 2021 09:00:00.000"`), it must be wrapped in double quotes as a whole.

- The parameter order must strictly follow the syntax definition and cannot be swapped.
