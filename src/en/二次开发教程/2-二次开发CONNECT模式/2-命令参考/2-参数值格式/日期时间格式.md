# Date/Time Format

Time parameters in commands take two forms: a date/time denoting a single instant, and a time interval denoting a span between two instants. How a date/time is written is determined by the current Connect Date unit: the Date unit fixes both the time system (Coordinated Universal Time, Beijing Time, BeiDou Time, and so on) and the representation form (a Gregorian date, or a numeric value such as a Julian day or seconds from an epoch).

Parameters that denote only a duration and do not refer to an instant, such as `"<Duration>"`, are entered in the Time unit and are outside the scope of this page; see [Unit Format](单位格式.md).

## Date/Time

A single time parameter in command syntax, such as `{TimeValue}`, `"<Epoch>"`, `"<OrbitEpoch>"` or `"<CoordEpoch>"`, is entered as described in this section. A date/time contains spaces, so the whole string must be enclosed in double quotes and passed to the command as a single parameter. Depending on the representation form of the Date unit, it is entered in one of two ways.

### Gregorian Form

The following units use the Gregorian date form. The date and the time of day are separated by a space, and the order of the date fields depends on the unit:

| Date Unit | Date Order | Example |
|------|------|------|
| UTCG_MM | year-month-day | "2023-07-29 09:19:01.000" |
| UTCG, BJT, BDTG, GPSG, TDTG | day month year | "1 Jul 2021 09:00:00.000" |

- With the day month year order, the month is written as a three-letter English abbreviation (Jan, Feb, Mar, and so on) and the day as a one- or two-digit number.
- With the year-month-day order, year, month and day are separated by hyphens, and the month and day each take two digits.
- The time of day is written as hour:minute:second, with as many fractional digits on the seconds as the required precision needs, for example .00 or .000.
- The same date string denotes different instants under different time systems: with the Date unit set to BJT it is read as Beijing Time, and with UTCG as Coordinated Universal Time.

### Numeric Form

When the Date unit is JDate, ModJDate, EpSec or another unit that counts days or seconds numerically, the instant is written as a single number:

| Date Unit | Meaning | Example |
|------|------|------|
| JDate | Julian date, counted in days | 2459580.5 |
| ModJDate | Modified Julian date, equal to JDate minus 2400000.5 | 59580.5 |
| EpSec | Seconds elapsed since the scenario reference epoch | 3600 |

When the Date unit is GPS or BDT, the instant is entered in the representation form of the corresponding time system. For the meaning and origin of each time system, see the epoch format description in [Analysis Period](../../../../03-基础使用指南/02-场景管理/03-场景属性配置/02-基本/01-仿真时间.md).

To set the Date dimension, use [Units_SetConnect](../4-Connect对象命令库/命令/Units_SetConnect.md) or the equivalent [Units_Set](../4-Connect对象命令库/命令/Units_Set.md); to query the current value, use [Units_Get](../4-Connect对象命令库/命令/Units_Get.md). For the available units, see the Date row of [Unit Format](单位格式.md).

## Time Interval

When a command contains the `{TimeInterval}` parameter, or has a paired `"<StartTime>"` and `"<StopTime>"` in its syntax, enter two values, a start time and a stop time:

```
"<StartTime>" "<StopTime>"
```

- The start time comes first and the stop time last; the order cannot be swapped.
- Both times are written in the same Date unit, each being a complete date/time.
- The two may be identical; when a report is retrieved, identical values mean that data is taken at that single instant.

## Examples

::: details open **Single instant** — set the ECI position and velocity of Satellite1 at a specified instant
```
SetPosition */Satellite/Satellite1 ECI "1 Jul 2021 09:00:00.000" 8678140.000000 0.000064 -1.837743 0.000781 6789.530412 3686.41396
```
:::

::: details open **Time interval** — create a report for Satellite1 over a specified period
```
ReportCreate */Satellite/Satellite1 Style "Position" File "linshi.rsf" TimePeriod "2023-07-29 09:19:01.000" "2023-07-29 10:09:38.000"
```
:::
