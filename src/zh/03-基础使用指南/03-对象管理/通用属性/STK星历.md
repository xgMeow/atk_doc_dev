# STK星历

STK星历预报器用于通过外部星历文件定义对象的运动轨迹，适用于飞机的航线、卫星的轨道及火箭的弹道等。用户可以直接加载符合格式要求的星历文件（`.e`），也可以通过星历转换工具将外部 TXT 轨迹数据转换为 `.e` 文件后导入。

## 参数设置

| 参数 | 说明 |
| --- | --- |
| 预报器 | 选择【STK星历】，使用外部星历文件定义对象的运动轨迹。 |
| 开始历元 | 星历数据的起始时间。导入文件后，根据文件中的时间信息确定。 |
| 结束历元 | 星历数据的结束时间。导入文件后，根据文件中的时间信息确定。 |
| 星历文件 | 指定要加载的 STK 星历文件路径。点击 `...` 选择已有的 `.e` 文件。 |
| 覆盖文件时间 | 勾选后，使用指定的首个星历点时间替代文件原有的时间基准；不勾选时，使用文件中的时间定义。 |
| 首个星历点的时间 | 启用【覆盖文件时间】后，设置首个星历数据点对应的时间，用于调整导入轨迹的时间位置。 |

## 直接导入 STK 星历文件

已有符合格式要求的 `.e` 文件时，可通过以下步骤加载：

1. 点击【星历文件】右侧的 `...`，选择要导入的 `.e` 文件。
2. 加载后查看【开始历元】和【结束历元】，确认时间范围符合场景需求。
3. 如需调整整段星历对应的时间，勾选【覆盖文件时间】，并设置【首个星历点的时间】；否则保持不勾选。

### STK 星历文件格式

直接导入的 `.e` 文件采用星历文件的文本结构，包括版本标识、星历数据块、配置字段、数据类型标识及逐时刻轨迹数据。

以下仅展示文件头和结束标记：

```text
stk.v.8.0

BEGIN Ephemeris

NumberOfEphemerisPoints   122
ScenarioEpoch            1 Oct 2029 00:00:00.0000
InterpolationMethod      Lagrange
InterpolationSamplesM1   5
CentralBody              Earth
CoordinateSystem         J2000

EphemerisTimePosVel

END Ephemeris
```

主要字段说明如下：

| 字段 | 说明 |
| --- | --- |
| `stk.v.8.0` | 文件格式版本标识，版本号随意，并置于文件开头。 |
| `BEGIN Ephemeris` | 星历数据块开始标记，必需。 |
| `END Ephemeris` | 星历数据块结束标记，必需。 |
| `NumberOfEphemerisPoints` | 星历数据点数量。 |
| `ScenarioEpoch` | 星历数据的参考历元；采用相对秒计时时，数据时间相对于该历元。建议明确填写。 |
| `InterpolationMethod` | 星历数据的插值方法，例如 `Lagrange`。 |
| `InterpolationSamplesM1` | 插值使用的样本点数减一；在 Lagrange 插值中也对应插值阶数。 |
| `CentralBody` | 星历数据所对应的中心天体，例如 `Earth`。 |
| `CoordinateSystem` | 星历数据采用的参考坐标系，例如 `J2000`。 |
| `EphemerisTimePosVel` | 指定后续数据采用“时间—位置—速度”格式。使用此格式时，后面必须提供相应的数据记录。 |

在 `EphemerisTimePosVel` 格式下，每条数据依次包含：

`相对时间(s)  位置X(m)  位置Y(m)  位置Z(m)  速度X(m/s)  速度Y(m/s)  速度Z(m/s)`

其中，时间为相对于参考历元的秒数。

上述配置字段并非全部必需，具体取决于 STK 文件格式版本、数据类型及 ATK 的解析支持情况。

对于分段轨迹，还可根据需要使用 `BEGIN SegmentBoundaryTimes` 和 `END SegmentBoundaryTimes` 标记分段边界时间。该段为**可选内容**；使用时须正确配对，不能将结束标记重复写成 `BEGIN SegmentBoundaryTimes`。普通连续星历无需添加该段。

## 星历转换工具

当外部轨迹数据尚未整理为 `.e` 文件时，可点击【导入数据】打开【星历转换工具】，通过导入 TXT 文件、配置坐标系及数据列映射，生成可供 STK 星历预报器加载的星历文件。

### 转换参数

| 参数 | 说明 |
| --- | --- |
| 历元（UTC） | 设置输入轨迹数据的参考历元；数据表中的相对时间以该历元为基准。 |
| 源坐标系 | 设置 TXT 文件中原始位置、速度数据采用的坐标系，可选【天体惯性系】【天体固定系】【发射系】【发射惯性系】。 |
| 目标坐标系 | 设置生成的星历文件所采用的目标坐标系，可选【天体惯性系】【天体固定系】【国际天球参考坐标系】。 |
| 弹道/轨道 | 选择待转换的外部轨迹 TXT 文件。点击【导入】读取文件数据。 |
| 数据列 | 指定 TXT 文件中各列数据与相对时间、位置和速度字段的对应关系。 |
| 生成 | 根据导入的数据及所选转换参数生成 STK 星历文件（`.e`）。 |

### 数据列映射

【数据列】功能用于处理外部 TXT 文件中数据列顺序与 ATK 默认顺序不一致的情况。通过指定列号，将输入文件中的各列映射到对应的时间、位置和速度字段，避免手动调整原始 TXT 文件的列顺序。

| 目标字段 | 含义 | 单位 |
| --- | --- | --- |
| 相对时间 | 轨迹数据点相对于所设历元的时间 | s |
| 位置X | 位置矢量 X 分量 | m |
| 位置Y | 位置矢量 Y 分量 | m |
| 位置Z | 位置矢量 Z 分量 | m |
| 速度X | 速度矢量 X 分量 | m/s |
| 速度Y | 速度矢量 Y 分量 | m/s |
| 速度Z | 速度矢量 Z 分量 | m/s |

界面示例中，七个字段依次对应列号 `0、1、2、3、4、5、6`。若 TXT 文件的列顺序不同，应按实际列位置调整映射关系。数据表会显示导入后的字段及对应数值，便于核对。

### 文件生成与加载

1. 点击 STK 星历属性页中的【导入数据】，打开【星历转换工具】。
2. 设置【历元（UTC）】，选择原始数据的【源坐标系】以及输出文件的【目标坐标系】。
3. 在【弹道/轨道】处选择 TXT 文件，点击【导入】读取数据。
4. 根据 TXT 文件的实际列顺序，调整【数据列】映射，并检查数据表中的时间、位置及速度。
5. 点击【生成】，输出 `.e` 格式星历文件。
6. 返回 STK 星历属性页，通过【星历文件】右侧的 `...` 选择生成的 `.e` 文件，完成加载。

星历转换工具支持对转换参数进行自动保存，关闭后重新打开时可复用先前的配置；再次导入其他文件时仍应检查坐标系和数据列映射是否适用。

## 使用注意事项

- 直接导入 `.e` 文件与通过【导入数据】转换 TXT 文件是两种不同的操作：前者加载已有星历，后者先生成星历文件再加载。
- 输入数据的时间应与【历元（UTC）】一致，且通常按时间递增排列。除规范允许的分段边界特殊情况外，不应出现重复时间点。
- 源坐标系应与 TXT 文件的实际数据定义一致，目标坐标系应与后续计算所需的坐标系一致；不同坐标系的数据不能只修改名称而不进行正确转换。
- 数据列映射错误会使时间、位置或速度字段错位，生成文件前应核对数据表。
- 如果设置【覆盖文件时间】，应核实调整后轨迹所处的时间区间是否满足场景需求。
