# 集群逻辑限定

集群逻辑限定用于设置集群成员在访问、链路及覆盖分析中的计算组织方式。既可以将成员分别参与计算，也可以将多个成员作为一个整体，根据**同时满足条件的成员数量**判定集群在某一时刻是否有效。

## 计算方式

| 计算方式 | 说明 |
| --- | --- |
| 独立计算 | 集群中的成员分别参与计算，各成员保留独立的有效结果，不使用集群级的成员数量条件进行合并判定。 |
| 打包计算 | 将集群作为一个整体参与计算，按照所选的**任意、全部**或**至少**逻辑限定，判断集群整体是否满足条件。 |

选择**独立计算**时，无需配置成员数量限定，**任意、全部、至少**等打包逻辑不参与计算。需要按多个成员的共同有效性确定集群结果时，选择**打包计算**。

## 逻辑限定

当计算方式为**打包计算**时，设置需要同时满足条件的集群成员数量。

| 逻辑限定 | 说明 |
| --- | --- |
| 任意 | 只要至少一个成员满足条件，集群整体即判定为有效。适用于多个成员可以互相替代的情况。 |
| 全部 | 只有全部成员在同一时刻均满足条件，集群整体才判定为有效。适用于所有成员必须同时满足条件的情况。 |
| 至少 | 有效成员数量达到或超过指定数量时，集群整体判定为有效。适用于只要求部分成员同时满足条件的情况。 |

### 数量

选择**至少**后，可以设置所需的最少有效成员数。设集群共有 `N` 个成员，要求至少 `K` 个成员有效，则 `K` 应取不大于 `N` 的正整数。

例如，集群包含卫星 A、B、C，设置为**打包计算 → 至少 → 2**。当 A 和 B 均满足访问条件、C 不满足时，有效成员数为 2，集群仍有效；如果只有 A 满足条件，集群无效。

下表给出三个成员条件下的判定示例：

| 同时有效成员数 | 任意 | 全部 | 至少 2 个 |
| --- | --- | --- | --- |
| 1 | 有效 | 无效 | 无效 |
| 2 | 有效 | 无效 | 有效 |
| 3 | 有效 | 有效 | 有效 |

上述判定使用的是**同一时刻**各成员的有效状态。成员在不同时刻分别有效，不能直接视为全部成员同时有效。

## 设置方法

1. 在集群对象的**基本 → 定义**中添加需要参与分析的成员。
2. 打开**约束 → 基本**，选择**独立计算**或**打包计算**。
3. 如需各成员分别参与计算，选择**独立计算**即可。
4. 如需整体判定，选择**打包计算**，再选择**任意、全部**或**至少**。
5. 当选择**至少**时，在**数量**中填写要求同时有效的最少成员数。
6. 点击**应用**或**确定**保存设置，进行相应的访问、链路或覆盖分析。

## 计算说明

- **任意**相当于要求至少一个成员有效；**全部**要求所有成员同时有效；**至少**要求满足条件的成员数量达到阈值。
- 逻辑限定用于组合成员的有效结果，**不修改各成员自身的轨道、位置或访问约束**。
- 当增加或删除集群成员时，应同步检查**至少**条件中的数量要求，确保其与当前成员总数相匹配。
