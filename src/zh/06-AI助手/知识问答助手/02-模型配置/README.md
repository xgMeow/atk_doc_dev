# 模型配置

问答助手同时依赖两类模型：问答模型负责理解问题并组织回答，嵌入模型负责把文档与问题转换为向量、支撑知识库检索。两者职责不同、调用接口不同，不能相互替代，也不能用一个模型兼任。

## 两类模型的分工与区别

文档入库时，嵌入模型把文档切分后的每个片段转换为一组数值（向量）存入向量库；提问时，同一个嵌入模型把问题转换为向量，系统按向量相似度取出最相关的片段。取出的片段与用户问题一并交给问答模型，由问答模型组织成自然语言回答。嵌入模型不直接产生回答文字。

| 对比项 | 问答模型 | 嵌入模型 |
|--------|----------|----------|
| 界面位置 | 主模型 | 知识库嵌入模型 |
| 主要作用 | 理解提问与检索到的片段，生成自然语言回答 | 把文档片段与提问转换为向量，供检索比对 |
| 调用接口 | 对话补全接口，输入上下文、输出文本 | 向量化接口，输入文本、输出向量 |
| 是否必需 | 必需 | 必需 |
| 更换的影响 | 只影响后续回答，已入库文档不受影响 | **已入库向量与新模型不在同一向量空间，用户文档库可能需要重建** |
| 典型模型 | 云端 deepseek-v4-pro、Qwen-Max、GPT 系列；本地 deepseek-r1、qwen2.5 | 云端 text-embedding-v4；本地 qwen3-embedding、bge-m3、nomic-embed-text |

## 两类模型不能混用

把问答模型填入知识库嵌入模型栏，是常见的配置错误。DeepSeek 提供的是对话模型，不提供向量化接口，因此不能用作嵌入模型：其模型列表中没有嵌入类模型，把 DeepSeek 的模型名称填入知识库嵌入模型栏也无法完成向量化。需要嵌入模型时，可改用提供向量化服务的服务商，例如千问的 text-embedding-v4，或在本地 Ollama 中下载嵌入模型。

判断一个模型属于哪一类，可参考以下线索：

- 服务商控制台按用途分类：标注「向量」「Embedding」的属于嵌入模型，标注「对话」「语言模型」的属于问答模型
- 模型名称：嵌入模型的名称通常包含 embedding 或 embed，例如 text-embedding-v4、qwen3-embedding、nomic-embed-text、bge-m3；对话模型的名称通常带 chat、instruct、r1、max 等字样
- 接口文档：嵌入接口的输入为文本、输出为向量，不返回自然语言

::: warning 问答模型的配置不能沿用到嵌入模型
两类模型可以来自不同服务商，需分别填写各自的 API Key、Base URL 与模型名称。若两类模型使用同一服务商的同一接入地址，API Key 与 Base URL 可以相同，但模型名称必须填写对应嵌入模型的名称；问答模型栏的模型名称不能沿用到嵌入模型栏。
:::

::: tip 常见组合
- 问答模型使用 DeepSeek，嵌入模型使用千问 text-embedding-v4，两者均走云端 API
- 两类模型都部署在本地 Ollama，问答模型使用 deepseek-r1，嵌入模型使用 qwen3-embedding
:::

## 配置入口

两类模型均在「参数设置」面板中配置。问答模型填写在主模型栏，支持兼容 OpenAI API 规范的服务，可调用云端 API，也可指向本地 Ollama。嵌入模型填写在知识库嵌入模型栏，调用方式由 Embedding 模式决定。

| Embedding 模式 | 需要填写的内容 | 前提 |
|----------------|----------------|------|
| API | API Key、Base URL、模型名称 | 已开通服务商的向量化服务 |
| 本地 Ollama | 模型名称、Base URL | 已安装 Ollama 并下载嵌入模型 |

填写完成后点击「测试连接」，连接通过后再保存配置。

## 选型建议

- 问答模型决定回答的准确性与表达质量。参数规模越大，推理与语言组织能力越强，对内存、显存的要求也越高
- 嵌入模型只负责生成向量，体积通常远小于问答模型，小参数规模的模型在本地 CPU 上即可运行
- 中文文档建议选择对中文支持较好的嵌入模型，例如 text-embedding-v4、qwen3-embedding、bge-m3
- 数据不能外传的环境可将两类模型都配置为本地 Ollama；两类模型也可以一个走云端 API、一个走本地 Ollama，互不约束
- 使用云端 API 时按 token 计费，嵌入模型的单价通常低于问答模型，费用主要集中在问答模型一侧

## 注意事项

- 嵌入模型决定向量库的形态。更换嵌入模型后，已入库文档的向量由旧模型生成，与新模型不兼容，用户文档库可能需要重建，重建会丢失已上传文档，请提前备份，参见[文档管理](../03-文档管理.md#注意事项)
- 模型名称须与已下载或已开通的模型一致。下载时指定了参数规模标签，配置中也填写同样的标签，例如下载的是 qwen3-embedding:4b，配置中就写 qwen3-embedding:4b
- 本地 Ollama 下两类模型的 Base URL 写法不同：主模型填写 `http://localhost:11434/v1`，知识库嵌入模型填写 `http://localhost:11434`
- 云端嵌入模型的 Base URL 由服务商决定，部分服务商使用业务空间专属地址，地址是否带 /v1 需按服务商文档填写
- 检索数量只影响每次检索返回的片段数，温度只影响回答生成，两者都不改变已入库的向量
- 语音识别模型与两类模型无关，仅用于语音提问，不配置不影响文字对话

## 配置步骤

根据运行方式选择对应页面：

- [本地模型配置](./本地模型配置.md)：通过 Ollama 在本地运行，数据不外传，需下载模型文件
